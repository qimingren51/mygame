# 提灯夜行 · 桌面版架构设计

> 状态：M2 完成（2026-10-12）。目标平台先做 Linux 和 Windows，技术栈为 Rust + Bevy。
> 玩法与数值设计见 `docs/GAMEPLAY.md` 和 `docs/BALANCE.md`，世界观与命名见 `docs/LORE.md`。M2 照搬网页版（`web/lantern/DESIGN.md`、`docs/PORTING-NOTES.md`）作为平衡基线，M2.5 起按这几份文档改。本文只讲技术架构。

## 1. 目标

| 目标 | 具体要求 |
| --- | --- |
| 模块化、易扩展 | 新增一个法器、妖物、夜签、奇遇，主要是加一份数据和图集帧。只有出现新行为时才写一个新系统，而且不改动已有模块。 |
| 性能 | 桌面上 5000 只妖物、400 个光源，稳定 60 fps（指标见第 16 节）。网页版的目标是 1000 只。 |
| 可复现 | 同一个种子加同一串输入，结果完全一样，Linux 和 Windows 之间也一样。回放、自动化测试、平衡模拟、错误复现都建立在这一点上。 |
| 不开窗口也能运行 | 模拟层不依赖窗口和显卡，可以在云端容器里跑测试、跑分、批量模拟。 |
| 可发布 | GitHub Actions 打出 Linux 和 Windows 安装包。以后可以接 Steam，也可以加 macOS 和 Steam Deck。 |

不在本阶段做的：联机、网页版、手机版、Mod 加载器（但数据格式按以后可以开放给 Mod 来设计）。

## 2. 技术选型

| 部分 | 选择 | 说明 |
| --- | --- | --- |
| 语言 | Rust 1.97（stable，edition 2024） | `rust-toolchain.toml` 锁定版本 |
| 引擎 | Bevy `=0.20.0` | 锁定精确版本，只在里程碑之间有计划地升级；关掉默认特性，只开 2D 需要的部分 |
| 数学 | `bevy_math`，开启 `libm` 特性 | 三角函数、指数函数走纯 Rust 实现，保证跨平台结果一致（第 7 节） |
| 数据格式 | RON（`serde` + `ron 0.12`） | 内容数据、存档、设置都用它，人和 AI 都容易读写 |
| 音频 | `kira 0.12`，直接使用 | 支持混音总线、滤波、精确到采样的时钟，音乐音序器需要这个。不经过 Bevy 插件，升级 Bevy 时少一个要等的依赖 |
| 调试界面 | `bevy_egui 0.43` | 只在 `dev` 特性下编译，发布版不包含 |
| 存档路径 | `directories 6` | 按各系统的规范目录存放 |
| 随机数 | 自己实现 PCG32，不依赖 `rand` | 算法不随依赖升级而变化，旧回放永远能重放 |
| 测试 | `cargo test`，`criterion 0.8` 做性能基准 | |
| 美术 | 沿用 Blender 无头渲染加 Pillow/numpy 后期（`art/`） | 只改输出目录 |

第三方 Bevy 插件尽量少用。插件通常要晚几周到几个月才支持新版 Bevy（例如 `leafwing-input-manager` 写这份文档时还停在 0.19），每多一个插件，升级时就多一个等待项。输入映射、图集加载、粒子都自己写，代码量不大。

## 4. 分层与依赖规则

```
game（可执行程序，只做组装）
 ├─▶ ui ─────▶ platform
 ├─▶ view
 ├─▶ audio
 └─▶ platform
        │  ui、view、audio、platform 都依赖 ▼
       sim ─▶ content ─▶ core

tools（命令行，不开窗口）─▶ sim、content、core
```

- 依赖只能向下（`ui` 另外依赖 `platform`，用来读取抽象操作；界面要出声时写 `platform` 里的 `UiCue`、`MenuSoundscape`，不依赖 `audio`）。`sim` 的 `Cargo.toml` 里只有 `bevy_app`、`bevy_ecs`、`bevy_math`、`bevy_state` 这几个子 crate，根本链接不到渲染、窗口和音频代码。分层由编译器保证，不再靠测试去扫描源码。
- `view`、`audio`、`ui` 只读模拟状态，再加上消费模拟发出的事件（第 6.7 节）；改变模拟的唯一方式是发送命令。
- 每个 crate 对外只暴露一个 Bevy 插件，例如 `SimPlugin`、`ViewPlugin`，再加上少量公开类型。`game` 只负责把插件组装起来，本身不写逻辑。

## 5. 主循环与状态机

**时间**：模拟在 Bevy 的 `FixedUpdate` 里运行，固定每秒 60 步，步长用常量 `1/60`，不读取真实时间。画面在 `Update` 里运行，用 `Time<Fixed>` 的超出比例在上一步和这一步之间插值。一帧最多补 4 步，卡顿时宁可让游戏变慢，也不让模拟连续追赶。

**状态**：

```
AppState:  Boot → Title（含灯驿、出发准备、夜签三选一、设置）→ Run → Title
RunState（Run 的子状态，只管界面）:  Playing ⇄ Paused，Playing → Over（结算）
SimPhase（模拟内部的资源）:  Play ⇄ LevelUp / Chest / Evolve / Lantern / Shop / Charm，Play → Over
```

- 一局之内的阶段 `SimPhase` 放在模拟里，**不用 Bevy 的 State**（M2 实现时改的决定）：State 要到下一帧开头才切换，一帧里补跑几步时，升级之后还会多跑几步，实际游戏和不开窗口的重放就对不上了。
- 每步开头记下这一步是否处于 Play（`StepGate`）。不是 Play 时只跑 Input：处理界面发来的 `Choose(i)`、`Reroll`、`Skip`、`Ack`，游戏时间不走。所以“选了什么”也被回放记录下来。
- 升级选项、宝箱内容由模拟生成（“选项”“宝箱”随机流），界面只负责展示和发命令。暂停（`RunState::Paused`）不属于模拟，暂停时 `FixedUpdate` 整个不跑，也不进回放。
- 开局前的夜签三选一在标题界面完成：用本局种子派生的“夜签”随机流抽 3 张。选定的夜签，连同心灯等级、生效的局外属性、灯、出发前挂的灯坠、已解锁的灯坠、更、悟·五行，一起写进 `RunSetup`（`Profile::run_setup` 拼出来），回放文件头里存的就是它。
- 标题切页、入夜与返回标题由 `ui/transition.rs` 的常驻墨幕承接：收墨、散墨各 0.24 秒，全遮挡帧绘制后才提交切换；目标贴图上传、渲染管线就绪并绘制首帧后揭开，慢设备可延长遮挡，最多等 3 秒（着色器坏了也照样揭开）。墨幕着色器嵌在程序里。灯驿长卷上的几个面板（灯驿、心灯、属性、成就、图鉴）之间切换不拉幕；墨幕盖着时灯驿的点灯、晨光动画暂停，揭开后再播。图集、卷轴、宣纸在标题期间预载并保留强句柄（`AtlasDb::images`、`view::SceneAssets`）。遮挡期间通过 `platform::InputSet::{Gather, Feed}` 之间拦截操作并停止定步循环，演出使用真实时间，不改模拟状态和回放命令。
- 结算提供“回灯驿”和“再来一夜”，都走墨幕。“回灯驿”在进入 Title 时消费一次性落点，直接打开灯驿（灯驿还锁着时回主菜单）；“再来一夜”保留 `RunSetup` 里的灯、灯坠、夜签，换一个种子（命令行给了 `--seed` 时照用），在遮挡下重入 Run 并把子状态设为 Playing，复用整局清理、开局与回放归档，不经过出发准备或夜签选择。
- 局内的选择阶段排队打开，顺序是：进化演出 → 升级 → 宝箱 → 点灯奖励 → 灯坠三选一。灯坠栏满了时，`Choose(i)` 先选新的一枚，再 `Choose(j)` 选换下哪一枚；`Skip` 在替换时返回、在三选一时放弃。

## 6. 模拟层（`lantern_sim`）

### 6.1 坐标与单位

- 世界单位和网页版的像素单位一致，所以数值表可以直接移植。y 轴向下，和旧版一致，由画面层负责翻转。
- 视野高度用固定的世界单位，宽度随窗口宽高比变化，最宽到 21:9。窗口越大，画面越清晰，但看到的范围不变，这样不同显示器上的游戏平衡是一样的。
- 模拟里的视野（刷怪圈、绕前距离）一律按最宽的 21:9 计算，与实际窗口无关，同一个种子在任何显示器上结果都一样，宽屏也看不到妖物凭空出现。

### 6.2 实体与数据

| 东西 | 存储方式 | 理由 |
| --- | --- | --- |
| 妖物 | 模拟内部的池子（`Enemies`，按字段分数组，槽位加代号的句柄） | 见下文 |
| 魂火（经验宝石） | 模拟内部的池子（`Gems`） | 数量大、行为单一，没人引用 |
| 主角、奇遇物件、地面区域（灵泉、地裂） | ECS 实体 | 数量少，各有行为，要挂不同的组件组合 |
| 伤害数字、粒子、墨迹 | 只在画面层有，模拟里不存在 | 纯视觉效果 |

**为什么妖物不用 ECS 实体**（M1 实现时改的决定）：
- 互推是按顺序原地修改位置的计算，结果取决于遍历顺序。如果妖物是 ECS 实体，画面层一给它挂上精灵组件，Bevy 就会把它挪到另一张表，遍历顺序随之改变，开窗口和不开窗口跑出来的结果就不一样，回放会失效。池子的遍历顺序只由模拟决定。
- 热路径（移动、互推、碰撞）连续访问同一字段，缓存友好，也没有创建和销毁实体的开销。
- 扩展性不受影响：妖物的种类、数值、移动方式都在数据里，状态效果（减速、冰冻、击晕、灼烧）是池子里的定长字段。

ECS 实体都有 `SimId(u32)`，按创建顺序递增，永不复用。对顺序敏感的逻辑用它打破平局，不依赖 Bevy 内部的 `Entity` 编号和查询顺序。

### 6.3 每一步的执行顺序

`FixedUpdate` 里用 `SimSet` 串成固定顺序：

```
Input（处理命令；选择阶段和演出停顿时只跑这一段）→ Player（移动、留火痕、回复、护盾、周期触发器、照见圈）
→ Director（刷怪、时间表、奇遇出现、竹丛生长）→ Ai（夜主出招）
→ Move（妖物移动、互推、接触伤害）→ Spatial（按移动后的位置重建空间网格）
→ Weapons（执行排队的触发器动作 → 法器 → 石印落地、地裂 → 轻功闪避伤敌 → 灯焰带
  → 反应区域（赤地、淤泥）→ 火痕 → 范围打击变成命中）
→ Projectiles（飞剑、金刃、弹幕）→ Collide（回光、九转金丹的震退）→ Damage（结算命中、命中触发器、印记与反应）→ Status（灼烧、竹丛受击）
→ Death（掉落、击杀触发器、连斩、燃灯充能、击败夜主）→ Pickup（魂火、拾取物、灵草、奇遇触碰）
→ Progress（升级；倒下、天明、打开升级或宝箱）→ Cleanup → Hash
```

- 伤害只有一个入口：法器和飞剑产生 `Hit`，范围打击（寒波、石印、爆炸、震地、太极、燃灯）先排进 `Strikes`，在 Weapons 末尾按空间网格找目标再变成 `Hit`；Damage 阶段统一结算。反应产生的伤害追加到同一个队列的末尾，本步结算。
- 演出停顿（第一次发生某种反应时停 0.3 秒）记在模拟的 `Hold` 资源里：Play 阶段接下来几步只跑 Input，时间不走。停顿属于模拟，回放和不开窗口的重放结果一样。
- 触发器里不针对单个目标的动作（回复、爆炸、震地、全屏伤害、追加飞剑、天降宝箱）排进 `ActionQueue`，下一个 Weapons 阶段执行。连锁爆炸因此一步传一层，和网页版一致。
- `FixedUpdate` 用单线程执行器：系统本来就串行，省掉每个系统唤醒工作线程的开销（实测约占 15%）。
- 往同一个队列写数据的系统，一律在同一个 Set 里显式串行。系统内部可以用任务池并行，但只限“每个对象只读快照、只写自己”的计算（例如互推），这样怎么分线程结果都逐位相同。
- 从并行代码里不能创建实体或改动池子。需要创建的东西先放进队列，串行阶段再按顺序处理。

### 6.4 空间网格

以玩家为中心的均匀网格（格子 64），每一步用计数排序重建（移植网页版）。用于法器命中、选目标等查询：圆形范围、最近的 N 个、线段扫过的格子（后两种在 M2 加入）。网格在妖物移动、互推之后重建，法器和反应按妖物这一步的位置查，夜主召唤、被拉回前方的妖物也查得到；之后才刷出、死去的妖物到下一步再进出网格（查询会跳过已经死掉的）。下一步主角阶段（照见圈）用的还是这张网格，那时妖物还没动，位置是准的。

**互推**单独用一套结构（`crowd` 模块）。网页版的做法在 5000 只围成一团时，平均每只要比较约 200 个候选，真正重叠的只有个位数。现在的做法：
- 普通体型（半径不超过 19.5）放进边长 34 的细网格，刚好覆盖两只普通妖物的最小间距，只查相邻 3×3 格；精英和夜主数量少，单独列表，每只都直接比较。
- 推力按本步开始时的位置快照计算，算完一起写回（网页版是按顺序原地改），结果与遍历顺序无关，可以分线程并行。
- 重叠时的开平方放在不内联的函数里，避免编译器把分支改成无条件计算。
- 实测（云端 4 核 2.1 GHz，跑分模式 5000 只围着主角）：互推加其余模拟每步平均 0.95 ms；单线程 2.2 ms；优化前 5.7 ms。

### 6.5 伤害管线

```
命中来源（法器、飞剑、范围打击 Strikes → 按网格找目标；灯焰带、赤地、轻功）
  → HitQueue（按产生顺序）
  → Damage：冰冻（命中前）
    → 加成区（× 伤害属性；反应、赤地已经乘过，跳过）
    → 暴击区（战斗随机流；被击晕且有“土生金”必暴）
    → 易伤区（照见或光区、熔金、冰冻相加，上限 +150%）
    → 克制区（法器的五行克妖物 ×1.25、同系 ×0.8；妖物带五行时才有，抢先体验起）
    → 夜主单次封顶 → 扣血 → SimEvent::Hit
    → 命中、暴击触发器（灼烧、减速、冰冻立即生效；其余动作排进 ActionQueue）→ 击退（淤泥里 ×2）
    → 点燃（火·极境的爆炸）→ 五行印记与反应（`sim/reactions.rs`）
    → 活着的附加击晕、减速；死了的放进 Deaths
  → Status：灼烧扣血（每跳乘一次易伤），死了的也放进 Deaths
  → Death：掉落（掉落随机流）、击杀触发器、连斩、燃灯充能、击败夜主
```

- 灼烧和反应以触发那一击“加成区之后、暴击和易伤之前”的伤害为基数，暴击和易伤不会被算两次（docs/BALANCE.md 第 3.1 节）。
- 控制：冰冻、击晕、定身是硬控，晕头是软控；夜主免疫，精英时长减半，同一只精英 6 秒内第二次 × 0.5、第三次起 × 0.25（硬控、软控分开计）。减速同类取最大、上限 70%，夜主减半。
- **印记与反应**：法器命中带着五行，给妖物打上 3 秒的印记；带着印记的妖物被另一系命中就反应，印记清空。每只妖物每秒最多反应一次，每一步最多 64 次；反应、灼烧、共鸣效果、燃灯不带五行，所以反应不会引起反应。十种反应写在 `elements.ron`（效果是 `ReactionEffect` 的一个变体：蔓延灼烧、地面区域、金刃、冻结、灵草、蒸腾、熔金、斩击、地刺），区域同类对同一只妖物只算最强的一块，每类最多 64 块。**余印**：带印记的妖物死时（命中、灼烧都算，在 `combat::kill` 里），印记传给 `marks.spread_radius` 以内还没有印记的妖物，最多 `spread_count` 只，重新计时；按空间网格的查询顺序挑，结果是确定的。
- **照见圈**（`sim/reveal.rs`）：规则半径，和画面的灯光分开。基础 130，每升一级 +1%，最大 220；照见圈里的妖物易伤 +10%。灯芯 1 级起，圈边 20 宽的一圈是灯焰带，每 0.5 秒结算一次伤害。
- 每次命中按来源（法器、灼烧、连锁爆炸、太极、燃灯、各种反应、灯焰带……）累计实际打掉的血（`DamageLog`），平衡工具用它统计伤害占比。妖物池另记累计刷出的血量（`Enemies::spawned_hp`），主角受伤的事件带着是谁打的（`SimEvent::PlayerHurt { by: HurtBy, from }`：碰撞、冲锋、弹幕、九尾扫、狐火雨，`from` 是伤害的来源位置，画面用它定受伤的方向），平衡工具据此算刷出血量和死因。这两样都不进状态哈希。

### 6.6 构筑：属性、修正与触发器（扩展性的核心）

旧版和 lantern-next 把每级数值写成函数，五行共鸣写成 if 分支。桌面版统一成三个概念（`lantern_content::effects`，汇总在 `lantern_sim::stats`）：

**属性（Stat）**：伤害、范围、冷却、数量、暴击、击退、灼烧、冰冻易伤、飞行物速度与持续、减速与冰冻、反应伤害、召唤物倍率、生命、护甲、减伤、回复、护盾、治疗、移速、拾取、灯光、照见圈与照见易伤、灯焰带、燃灯充能、闪避（冷却、段数、距离、伤敌）、重抽、封印、选项数、灵光一闪、宝箱、刷怪、妖物血量与移速、精英数、奇遇频率、灯油与铜钱倍率、法器栏与灯坠栏、灯坠和心灯的规则参数（站定、火痕、照见圈外移速、冰冻魂火、受击反冻、回光、余烬），共 72 项，用一个枚举表示。基础值和上下限在 `stats.ron`。最终值 = clamp((基础值 + Σ加值) × (1 + Σ乘值), 下限, 上限)。伤害只许写 `Add`（加成区相加，内容校验会拒绝 `Mul(Damage, …)`）；暴击、易伤、克制是结算时的独立乘区。照见圈和灯光的“每级 +1%、+0.5%”在汇总时按等级加进乘值，升级时重算。

**修正来源**：心灯、局外属性、灯、灯坠（这四项是局外带进来的）、更、夜签、心法（每级）、五行共鸣各阶、相生、太极、古灯增益。规则开关 `Rule(…)`（无生、无月、夜主多一招、九转金丹）和“按共鸣阶数计”的 `ByTiers`（五帝钱）也在汇总时算出。来源变化时把属性标记为需要重算（`StatsDirty`），在下一个刷新点统一重算；周期触发器重算后保留已经过的时间。

**效果**写在数据里：

```ron
Add(CritChance, 0.10),                                            // 属性加值
Mul(Magnet, 0.25),                                                // 属性乘值
Trigger(on: Hit, action: Burn(duration: 3.0, ratio: 0.2)),        // 火·焚 一阶
Trigger(on: Crit, chance: 0.5, only: NotBonus, action: BonusSword(...)),  // 金·锐 三阶
Trigger(on: Kill, only: TargetFrozen, action: Explode(radius: 52.0, damage: (10.0, 5.0, 0.0), kind: Ice)),
Trigger(on: Periodic(30.0), action: ScreenDamage(damage: (40.0, 16.0, 0.0), boss_cap: 600.0)),  // 太极
Shield(amount: (20.0, 5.0, 0.0)),                                 // 土·固 一阶
Points(2), Favor,                                                 // 夜签“五行偏重”
```

- 时机：`Hit`、`Crit`、`Kill`、`ShieldBreak`、`Periodic(秒)`；条件：`TargetFrozen`、`NotBonus`、`ThirdHit`（同一只妖物的每第 3 次命中）；概率 `chance`。
- 动作：`Burn`、`Slow`、`Freeze`、`BonusSword`（每秒最多 30 把）、`Heal`（满血时多出的部分可以转成护盾）、`Explode`（可带冰冻、点燃）、`Quake`、`ScreenDamage`、`DropChest`。
- **共鸣**按投入计点（法器 Lv1–3 / 4–7 / 8 / 进化 = 1 / 2 / 3 / 4，心法 Lv1–2 / 3–4 / 5 = 1 / 2 / 3，表在 `elements.ron`），阈值 3 / 7 / 12 / 20 对应一阶到极境。标了 `superseded` 的一阶在到了下一阶后不再生效，由下一阶写的加强版取代（例如金·极境的“每次暴击都追加”取代三阶的“50% 追加”）。无属性心法（轻功、聚魂）不计点。
- **升级选项**：权重同网页版，已到一阶的五行 ×1.5；灵光一闪的概率是属性 `Inspiration`。保底：前 5 次升级至少出现 2 件不同的新法器；法器 Lv7 以上缺进化心法时，每次升级 25% 把那门心法放进选项（`run.ron` 的 `pity`）。封印（`SimCommand::Banish`）把选中的一项永久移出本局卡池，换一个新选项，次数来自属性 `Banishes`。
- 新增一种动作 = 给枚举加一个变体，再在 `lantern_sim::combat` 里写处理分支。之后任何法器、共鸣、夜签、心法都能用它。M2.5 的五行反应、灯坠按这个方式加（docs/GAMEPLAY.md 第 16 节）。

**法器** = 行为 + 每级数值表 + 五行 + 正统进化 + 可选异化（`WeaponDef.mutation: Option<MutationDef>`，含 `name / desc / flavor / behavior / level`，共用正统的心法钥匙，行为和原法器同一种）。行为在 `sim/weapons/` 里，一种一个文件：`Orbit` 环绕（灯火）、`Volley` 追踪齐射（符剑，也负责全部飞剑的飞行）、`Pulse` 震波（霜铃，进化后加全屏钟鸣）、`Seeker` 扑击（纸鹤）、`Drop` 落印（山印，进化后留地裂）。用已有行为做新法器，只需要写数据。

**异化与合璧**（EA 内容，docs/GAMEPLAY.md 第 6.5、6.6 节）由 `run.ron` 的 `transformations: bool` 开关，不写时为 false，数据里也写着 false。关着时 `can_mutate`、`can_fuse` 一律为假：不出 `Mutate` / `Fuse` 卡，质变卡保底、封印后重整整组都不启用，进化卡说明和信息栏的星标照旧。要打开：`lantern-tools kite --transformations`（`--fusion` 自动打开），测试里调 `Content::enable_transformations()`；它同时改内容哈希，打开时录的回放不会在关着的版本上重放。

- **形态**：`WeaponSlot.form` 是互斥的 `Form::Base | Evolved | Mutated | Fused(fusion_id)`。`behavior()`、`stats()`、`name()`、`desc()`、`flavor()` 都按形态读取；`transformed()` 只表示已质变，不代表有合璧资格。`can_mutate` 要求开关打开、能正统进化，另持有克制本系的任意满级法器。进化或异化后不能改选，进化不重置法器的计时和纸鹤。异化本系计四点。
- **合璧**：`fusions.ron` 定义三种合璧，`FusionDef { id, name, desc, flavor, weapons: [String; 2], behavior, level }`，RON 里写成 `weapons: ("crane", "lamp")`。加载时校验：材料存在、不同、各有正统进化和异化（正统与异化二选一是合璧的代价）、五行相生、行为和第一件材料同一种，以及行为数值和未知字段。`can_fuse` 在抽卡和应用时都核验两件 `Form::Evolved`、两系至少二阶和封印。合璧用一个槽替换两件，挂在第一件材料上；材料仍视为持有，不能重新抽回；两系各计四点。`occupied_slots` 统一容量判断：通常一格；挂着限制法器件数的灯坠（`max_weapons`，断剑）时两格，抽灯坠也按材料数判断。
- **选项**：`Offer` 增加 `Mutate(k)`、`Fuse { a, b, fusion_id }`，权重和进化一样是 `weight_evolve`（1000）。质变卡保底（`build.rs` 的 `arrange_forms`，只在开关打开时）：合璧每次升级、重抽必展示；有分岔时同屏保证正统与异化成对，优先最先持有的一件；没有分岔时保一张正统进化。保底放进来的新法器、心法钥匙也一定留住，卡多时多展示几张。封印某件法器会移除它的进化和异化；封印合璧只移除这一个合璧（`Banned::Fusion`）。质变牌封印后重抽整组，免得另一张失效卡残留。宝箱不替玩家选：有异化分岔的进化和合璧不进宝箱。
- **行为扩展**（都是可选字段，数值全在 RON 里，加载时校验）：`Orbit.ice_fire: IceFireDef { freeze, ignite }` 冰焰、火焰交替；`Volley.molten: MoltenDef { vulnerability, duration, split: Option<SplitDef { count, ratio, range, speed, life, turn, hit_radius, knockback }> }` 熔金与击杀分剑；`Pulse.permafrost: PermafrostDef { shatter_radius, shatter_ratio, shatter_budget }` 常驻冻土与碎裂，`Pulse.ice_rain` 钟鸣剑雨；`Seeker.feather: FeatherDef { pierce, speed, life, ratio }` 铁羽（伤害 = 扑击 × ratio），`execute` 斩杀，`count_cap` 固定只数，`on_hit: ImpactDef` 余爆和凤火，`escort: EscortDef { radius, every, ratio, spin, size }` 绕身巨凤。
- **地面区域**：`FissureDef.kind: GroundKind` 区分地裂、凤火、竹墙、剑林，`FissureDef.wall: Option<f32>` 是竹墙的移速倍率。它们（包括镇岳的地裂，不论开关）共用 `Fissures` 区域池（`weapons::drop::update_ground` 跳伤害），全场至多 `run.ron` 的 `ground_cap`（64）块，满了替换最早的一块。区域跳伤害时同类对同一只妖物只算每秒伤害最高的一块（相同取最早），也和范围打击一样打竹丛；不打印记、不引起命中连锁。竹墙：普通妖物降到墙的倍率（0.12，是墙不是减速，不受减速上限）；精英按一般减速算，最多减 70%（`combat::SLOW_CAP`）；夜主和奇遇小动物不受影响；和地图竹丛不连乘，取更慢的一个；冲锋不减。移动阶段每步把竹墙收集一次再逐只查。
- **其他**：分剑随 `Hit.molten` 带着熔金参数，分出的剑 `split = None` 不再分裂，找目标复用缓冲，飞剑总量仍受 512 上限；冻土碎裂每步至多 `shatter_budget` 次，`HIT_SHATTER` 阻断碎裂连锁；精英和夜主不被碎裂或斩杀。状态哈希也记法器内部计时和纸鹤状态（`Arsenal::hash_detail`）、飞行物的寿命伤害和效果（`Shots::hash_detail`）、区域池和待落石印、封印明细。

**妖物** = 数值 + 移动方式（追击、逃跑）+ 精灵 + 等级（普通、精英、夜主、奇遇小动物）。夜主的招式参数写在 `enemies.ron` 的 `boss` 里（弹幕、召唤），逻辑在 `sim/boss.rs`；M2.5 起每个夜主一个状态机。

### 6.7 模拟与外界的接口

| 方向 | 形式 |
| --- | --- |
| 输入 → 模拟 | 每一步一个 `InputFrame { mx: i8, my: i8 }`。摇杆和键盘的方向先量化成 i8 再交给模拟，实际游玩和回放看到的数值完全一样。 |
| 命令 → 模拟 | `SimCommand` 队列：闪避、燃灯、选择第几项、重抽、跳过、封印、确认（宝箱、进化演出）。每条命令带上步序号，写进回放。 |
| 模拟 → 外界 | `SimOutbox` 里一个 `Vec<SimEvent>`，存放小的 Copy 枚举（命中（带这一击的五行，画面按它上色）、击杀、拾取、受伤、闪避、升级、共鸣、进化、首领登场、震屏、闪光……）。一帧里可能跑了好几步，事件会累积起来；画面、音频、界面消费完之后，在 `Last` 阶段统一清空。Vec 保留容量，预热之后不再分配内存。 |
| 外界读取状态 | 直接查询组件和资源（只读）：`SimPhase`、`Flow`（当前的选项、宝箱、结算）、`Arsenal`、`Build`、`Stats`、飞剑、弹幕、拾取物、奇遇…… |

在 `Play` 阶段处理燃灯命令时，充能不足会发出 `SimEvent::UltNotReady`。界面据此抖动整条燃灯计量槽并短暂显示“灯火未满”，音频复用提示鼓点；计时、淡出和音效限频留在表现层。事件由命令和模拟充能值确定，不改变玩法状态或随机流，也不进入状态哈希。

打击身份事件契约（仅表现用，见 `FEEL.md` 第 10 节）：

- `SimEvent::Hit` 保留 `pos` 的飘字语义，新增 `impact_pos: Vec2`、`incoming_dir: Vec2`、`weapon: Option<u16>`、`source: combat::Source`、`target: EnemyHandle`。接触点为敌人中心减入射单位方向乘敌人半径。飞剑、纸鹤可把当前速度附在瞬时 `combat::Hit.incoming`；否则取 `from→目标`，重合时取 `主角→目标`，再重合为零方向、接触点为中心。
- `Source::Weapon(i)` 的 `weapon` 为内容下标；`BonusSword` 按 ID 查找 `sword`，缺失为 `None`；灼烧、反应、燃灯等非法器来源为 `None`。`Source` 保留来源类别，用于给无元素字段的灼烧 / 反应脉冲上色。
- `SimEvent::Kill` 增加 `target`、`weapon`、`incoming_dir`；`Death.hit: KillingHit` 保存最后一击的来源和方向。范围打击、反应走统一结算，灼烧死亡显式传 `Burn + ZERO`。句柄包含代号，槽位复用不会把旧受击表现套到新妖物上。
- 这些数据只写到临时伤害 / 死亡记录与事件里，不参与伤害、击退、控制、随机流或状态哈希。事件仍为 `Copy`，不含堆分配。`Enemies.flash` 的原模拟值保持原样；画面改由事件驱动自己的计时。
- `content::WeaponIdentity` 按字符串 ID 给 view / audio 提供相同归属，未知 ID 使用通用表现。`view::impact` 保存句柄对应的受击曲线与最后可见姿态；精灵池在变换传播之后、可见性检查之前应用纯渲染仿射矩阵。每帧从原始 `Transform` 重建，暂停时不叠乘形变。死亡残留使用 `fx` 一次性池的低优先级槽位，不修改模拟资源。

质变沿用 `SimPhase::Evolve` 和两秒水墨演出，`SimEvent::Evolve { weapon, form }` 区分正统、异化、合璧。界面用不同印文和角标（开关关着时信息栏照旧画星），音频按形态调锣声；合璧转场同时显示两枚材料图标。`StrikeFx::Bamboo / SwordGrove` 区分巨竹上冲和群剑落地的镜头、粒子、音色。

### 6.8 导演（单局节奏）

`assets/data/run.ron` 描述一局的全部节奏：总时长、刷怪速率曲线（再乘过渡系数，P0 是 0.7）、杂兵和精英各自的血量曲线、升级所需经验曲线、妖物配比、成群涌来的妖物、时间表、掉落、铜钱、点灯、升级选项权重、连斩、灯油。曲线用二次多项式系数表示。奇遇在 `events.ron`（间隔 40–65 秒）。夜签和“更”通过和属性一样的修正机制改这些参数（`SpawnRate`、`EnemyHp`、`EnemyDamage`、`BossHp`、`Affixes`……）。音乐配器由音频层只读妖物数量、近身威胁、生命、受伤事件、时间进度和夜主状态决定，平滑和滞回后按乐句切换（`FEEL.md` 第 6 节）。

- **构筑节奏**：Lv7 缺心法每次升级 25% 提示不变，`choices.pity.key_guarantee_after = 300` 后满级缺钥匙必展示（需心法空格，受封印约束）；五分钟小头目宝箱的每项优先补最接近进化的法器；宝箱没有可升的给灯油，不放开新法器、新心法。没有自动满级、自动送心法或时间硬锁。
- **3／6／9 分钟验收**（异化与合璧打开时）：共鸣仍是三点一阶、七点二阶。`lantern-tools kite --fusion phoenix|sword_grove|frost_rain|all --assert-build-pace` 跑真实刷怪并检查窗口：一阶中位不晚于三分钟，首次进化／异化中位四至七分钟，定向路线至少半数合璧且中位不晚于九分半。不开局外成长、开启无敌只为观察完整局的样本口径，不能当作玩家胜率。
- **上限**：常规刷怪按分钟分段停刷（300 / 600 / 1000 只）；妖群、合围、妖潮不受常规上限限制；任何刷怪都不超过硬上限 2000（`spawn_enemy` 里检查）。
- **时间表**（P0 青丘，docs/BALANCE.md 第 4.6 节）：精英、合围（预警 1 秒，画面上屏幕四边起墨雾；之后在视野外围成一圈，2.2 倍速合拢，进入 200 以内恢复原速）、5:00 小头目青面鬼（不带词缀，宝箱至少三连并优先升级最接近进化的法器）、精英、合围、8:00 妖潮、9:30 夜主（之后常规刷怪 ×0.4，并以主角为中心生成半径 600 的结界，主角出不去）。
- **更**（`difficulty.ron`）：每一更是一组修正效果，作为一个修正来源计入属性；三更的“夜主多一招”是规则开关 `Rule(BossExtra)`。`RunSetup.tier` 记在回放文件头里。
- **冲锋**（`enemies.ron` 的 `charge`，docs/BALANCE.md 第 12.6 节）：赤面狐扑击、青面鬼冲撞。妖物池里记阶段（冷却、蓄力、冲出、收势）、剩余时间和方向：离主角够近且冷却好了就原地蓄力（转向跟着主角，画面上身上发亮、地上画冲锋线；出手前 `lock` 秒锁定方向，线停下、变亮），然后冲出，接触伤害乘倍率，冲完原地停一会儿。冻住、击晕、定身、晕头会打断蓄力和冲锋。冲锋速度不吃“疾”“狂”和难度的移速加成。
- **精英词缀**（`affixes.ron`）：疾、坚、分、召、隐、狂；精英出场时按属性 `Affixes` 随机挑几个不重复的，记在妖物池的位掩码里。“隐”在照见圈外时自动瞄准锁定不到（空间网格的最近查询跳过它），范围伤害照样打得到。“分”死后分出几只小号（不算精英、不掉宝箱和铜钱）。
- **夜主**（`sim/boss.rs`）：九尾按生命分三个阶段：狐火环与召唤；分出幻身（`BossState.illusions`，不是妖物、打不死，在照见圈里待 0.5 秒就散）；九尾扫（扇形，预警后结算）。登场 120 秒后狂暴，攻击间隔 ×0.6；三更起全程多一招狐火雨。本体与幻身狐火环共用 `boss.volley_warn`（0.8 秒）；起手锁定原点、随机方向和弹丸参数，完整等待预警后出手，狂暴只缩短起手间隔。蓄力中的本体与幻身停在施法位置，幻身照散或夜主离场取消未出手的预警。`BossState` 保存并哈希蓄力参数、计时和落点，`VolleyWarn` 只向音画层报告起手；`BossVolley.illusion` 区分本体与幻身出手，只供音画消费，不进入状态哈希。本体动画只响应本体的发射。全部点亮石灯笼时夜主少两成生命。台词在 `enemies.ron` 的 `boss.lines`（登场、第二阶段、第三阶段、倒下；无尽夜里的退去、再来，docs/LORE.md 第 7 节）：换阶段、退去的那句出在提示条上，登场和天明的演出由 `moments.rs` 决定怎么用。
- **竹丛**（`sim/bamboo.rs`，`run.ron` 的 `bamboo`，docs/BALANCE.md 第 12.7 节）：青丘的软障碍，不挡路。地图按 512 的块生成：主角周围 5 × 5 块里还没长过的，按“种子 + 块坐标”派生的随机数（`Streams::derive`，不消耗随机流，同一个种子地图一样）长出竹丛，避开出生点和石灯笼；长过的块一直记着。查询用主角周围一张 64 格的表，主角换块时重建。主角和妖物站在立着的竹丛里移速 × (1 − slow)，闪避和冲锋不减。法器（灯火、飞剑和刃、纸鹤出手、不夜城内环）、范围打击（石印、寒波、燃灯……）、反应（蒸腾、崩裂、赤地）、灯焰带、风火轮的火痕打到竹丛时往 `Bamboo.hits` 记一笔，Status 阶段结算：每丛取最大的一笔，之后隔 `hit_every` 秒才再受伤；不经过命中管线，所以不打印记、不触发心法和灯坠、不计连斩。打碎发 `BambooBroken`，按概率掉一枚铜钱，`regrow` 秒后主角不在附近时长回来。奇遇和货郎出现时让开周围的竹丛；夜主的结界出现时，结界里的竹丛烧平（`BambooBurned`），这一夜不再长。画面按状态画立着的、打碎的、焦黑的竹丛。
- **点灯**（`sim/lanterns.rs`）：开局把出生点周围分成 5 个扇区，每个扇区一盏，离出生点 600–1800。站在旁边累计 3 秒点亮，进入点灯奖励的选择阶段（回复、一次升级、铜钱）。点亮的灯是永久光区：区里的妖物减速、算被照见。
- **铜钱**（`sim/gold.rs`）：和魂火一样在模拟里，但不会自己飞回来；拾取范围、引魂铃会吸过来，天明时剩下的全部算进结算。倒下时已经捡到的全部保留。
- **燃灯**：每击杀一只妖物充“它的最大生命 ÷（基础刷怪曲线每秒刷出的总血量 × 40）”，精英额外 +15%；对夜主每次不超过最大生命的 2.5%。
- **货郎**：碰到后进入商店阶段，用铜钱买宝箱（`Choose(0)`）或一次灯坠三选一（`Choose(1)`）。
- **灯坠**（`sim/charms.rs`）：数值类的只是修正来源；规则类在模拟里结算——定海神针看主角站定的时间（`Player.still_t`），把站定、移动的加成算进加成区；风火轮在闪避路线上每隔一段留一段火痕，每 0.5 秒烧一次；照夜珠让照见圈外的妖物变快；冰魄珠让冰冻中死去的妖物魂火翻倍；霜瓷灯受击时按概率冻住攻击者。局内三选一：5:00 小头目必给，精英宝箱 30% 附带，货郎可买；只从 `RunSetup.charm_pool`（已解锁）里抽，不出已经挂着的、不出碎掉的金丹，法器多于 4 件时不出断剑。没有能给的灯坠时，宝箱改给 20 铜钱，货郎这一项灰掉（`Shop.charm_ok`）。
- **余烬**：开局第一步结束时打开一次只有心法的三选一（`Choice.ember`），权重同升级，能重抽、封印、跳过（跳过不给灯油）；选中的心法直接到节点等级。
- **减伤**：减伤合计（含定海神针的站定减伤）最多 60%。
- **救命**：致命一击落下时先试回光（心灯，留 1 点生命，2 级再回复 30%，震退周围），再试九转金丹（回复 50%，震退全屏、清掉弹幕，金丹碎掉）。记录在 `Survival`，同时记下受伤次数，用来判断“不受伤击败精英”。
- **灯笼叠层**（画面）：主角帧里只有灯杖，灯笼按这一局的灯画在主角上面：同一动作、同一朝向、同一帧号的 `lantern_<灯>/<动作>_<方向>_<帧号>`，自发光用它的 `_emit`；灯光半径不变，光色把灯的颜色淡淡地混进暖光。图集里没有这盏灯的叠层时不画灯笼，也不退回红纸灯。
- **结算统计**：`RunResult.feats` 记下见过的反应、太极、最高共鸣阶、手上同时最多几件法器、无伤击败的精英、受伤次数，存档按它判断成就。
- **10 分钟以后**（`run.ron` 的 `late`，docs/BALANCE.md 第 4.1 节）：刷怪、杂兵和精英生命改成线性增长，= 10 分钟时的值 × (1 + 斜率 × (m − 10))（`RunDef::late_at`）。普通一夜过了 10:00 的夜主战也按它算。
- **无尽夜**（`RunMode::Endless`，`run.ron` 的 `endless`，docs/GAMEPLAY.md 第 3.4 节、BALANCE.md 第 4.7 节）：前 10 分钟和普通一夜一样。夜主倒下不设 `won_at`，事件 `BossDefeated { dawn: false }`（画面和音效据此不演天明），结界撤掉，夜续下去。10 分钟以后每 5 分钟（15:00、20:00……）照时间表里的妖潮再来一次，妖潮结束时照时间表里的夜主再来；上一个还在场就等它倒下。第 k 次再来的夜主生命 × 1.25^k。进度记在 `Director.endless`（第几波、夜主该来的时刻、来过和倒下几次、10 分钟以后的击杀），无尽夜时进状态哈希。**夜深**（`endless.depth`，BALANCE 4.7）：10 分钟以后每过一分钟，杂兵和精英生命按 `hp_growth` 复利涨（取代线性的 `late.hp`，妖物池开局记下 `Enemies::endless`，`spawn::hp_curve` 按它挑曲线；燃灯的充能分母 `base_spawn_hp` 也跟着这条曲线），妖物移速（含冲锋）线性涨，魂火按 `xp` 复利打折，抗控制 r 线性涨到 `control_max`：冻住、击晕、定身的计时每步减 DT × (1 + 4r)，减速和击退 × (1 − r)；每次 10 分钟以后的妖潮发 `SimEvent::NightDeeper { layer }`，提示条写“夜深 · 第 N 层”。倒下才结束：灯油前 10 分钟照常，之后每秒 0.5、击杀 × 0.01，第一个夜主算天明 300、再来的每个 150；10 分钟以后铜钱掉落减半。`RunResult` 记 `endless` 和打倒的夜主数 `bosses`。

## 7. 确定性与回放

**规则**（`sim` crate 里用 clippy 的 `disallowed-methods` 强制执行）：

1. 步长是常量。不读系统时间，不读帧时间。
2. 所有随机数来自按用途划分的随机流：夜签、开局、刷怪、战斗、掉落、奇遇、选项、宝箱。每个流是一个 PCG32，由本局种子经过 SplitMix64 派生。地图上按块生成的东西（竹丛）用 `Streams::derive(键)`：只由种子和键决定，和各条流抽了多少次无关。
3. `sin`、`cos`、`atan2`、`exp`、`powf` 一律用 `bevy_math::ops`，并开启 `libm` 特性。直接调用 `f32::sin` 这类方法会报错。加减乘除和 `sqrt` 在各平台上都是 IEEE 精确的，可以直接用。
4. 不遍历 `HashMap` / `HashSet`。需要按顺序遍历的地方用 `Vec`、`BTreeMap` 或者排好序的数据。
5. 只在“每个实体只写自己”的地方使用并行，往队列里写的阶段一律串行。
6. 纯装饰的随机（粒子、震屏）放在画面层，用单独的随机数，不影响模拟。

**状态哈希**：每 60 步计算一次哈希。把实体按 `SimId` 排序，再把位置、血量、状态、随机流状态、玩家数据、构筑一起算出一个 u64。

**回放文件**（RON，格式版本 2）：
- 文件头：游戏版本、内容数据哈希、完整的开局设置 `RunSetup`（种子、模式、夜签、心灯等级）。
- 内容：按“步”录制。每一步的输入（游程编码），带步序号的命令，每秒（游戏时间）一个状态哈希。升级选择等阶段游戏时间不走，但这些步也录下来，选择命令记在它生效的那一步。
- 解析时校验输入总步数、命令顺序和范围、逐秒检查点的完整性；重放时逐秒核对哈希，不一致就报告第一次出现分歧的步数。只有输入、命令和检查点全部消费，且实际 tick 与声明一致，才报告全部一致；提前结束报告不完整。
- 只有游戏版本和内容哈希都相同时才保证能重放。

**黄金测试**：固定几个种子，加上脚本化的输入，模拟 3 分钟，把每秒的哈希写进 `crates/sim/tests/golden/*.ron`。CI 在 Linux 和 Windows 上都跑这个测试并对照同一份文件，跨平台不一致会立刻发现。故意修改玩法时，用 `UPDATE_GOLDEN=1` 重新生成。

**录制与保存**（M1 已实现）：
- 每局都录，录制在模拟内部 `SimSet::Input` 的最前面完成，录到的就是模拟实际看到的输入和命令。
- 游戏中每 10 秒把当前回放写到数据目录的 `replays/current.ron`，万一崩溃，最近的一局也还在；一局结束时存成 `replays/<时间>-<种子>.ron`，只保留最近 20 局。
- 观看：`lantern --replay <文件>`，跳过标题直接开局，屏幕上方显示回放状态，与录制时的哈希不一致时提示从第几步起分歧，播完暂停。
- 校验：`lantern-tools replay <文件>`，不开窗口重放，逐秒核对。M1 实测：游戏里录的 30 秒回放，不开窗口重放 0.5 秒，30 个检查点全部一致（也就是说带画面、帧率不稳定的实际游玩，与不开窗口的模拟结果逐位相同）。M2 实测：游戏里录的 3 分 23 秒整局（含 11 次升级选择、夜签），203 个检查点全部一致。

**用途**：遇到 bug 时，把 `replays/` 里对应的文件发过来，我在云端用 `lantern-tools replay` 就能原样复现。

- 数据结构用 `serde` 定义在 `lantern_content` 里，游戏和命令行工具共用同一套。
- 加载后统一校验：ID 不能重复、引用必须存在、每种行为需要的数值都在、概率在 0 到 1 之间、效果只能用在允许的地方。`cargo test` 会校验仓库里的全部数据文件。游戏启动时如果校验失败，直接显示哪个文件出了什么错（RON 语法错误带行列号）。

- 灯坠、灯、奇遇、法器（连同进化）、心法的一句话描述（`flavor`，docs/LORE-TEXT.md 第 3 节）写在各自的数据里，没有就不显示。法器和心法只在“新”和“进化”的卡片上显示，升级卡不重复。
- 名字和说明（法器名、心法说明、夜签好处……）目前直接写在数据里（中文）；界面上的固定文字写在 `crates/ui` 的代码里。`fonts.py` 扫描这两处裁剪字体。加第二种语言时再把文字移到 `assets/i18n/`，数据里改存文本键。

## 9. 画面（`lantern_view`）

### 9.1 图层（从下到上）

| 图层 | 内容 | 混合方式 |
| --- | --- | --- |
| 宣纸 | 平铺的纸纹 | 普通 |
| 接触阴影（z=9） | 角色、妖物、立式地景脚底的软椭圆 | 普通（黑色透明贴图） |
| 地面 | 装饰、墨迹（环形缓冲，旧的逐渐淡掉） | 普通 |
| 角色 | 玩家、妖物、投射物，按脚底 y 排序 | 普通 |
| 暗层 | 光照图（9.2 节） | 正片叠底 |
| 前景（z=205） | 带微虚边的近景墨竹，边缘框景 | 普通 |
| 火焰 | 灯笼火、法术特效 | 普通或叠加 |
| 自发光 | 妖物的眼睛、魂火、辉光 | 叠加 |
| 危险描边（z=240） | 九尾扫、狐火雨、冲锋；高于前景和自发光 | 普通或叠加 |
| 伤害数字 | 位图数字精灵（不用文本渲染） | 普通 |
| 屏幕效果 | 闪光、暗角 | 普通 |

- 角色用 Bevy 自带的 Sprite 加图集。z 值由图层基数加上 y 乘以一个小系数得到。同一张图集里的精灵会被自动合批，5000 只妖物大约只需要几次绘制调用。
- 妖物和魂火在模拟的池子里，画面层用一个固定大小的精灵池，每帧按池子的数据填充（只画视野内的），不随妖物生死创建、销毁实体。死亡特效由 `SimEvent::Kill` 另外生成。主角等 ECS 实体由 Observer 补上画面组件。

### 9.2 光照图

- 光源是带径向渐变的精灵，放在单独的渲染层上。一台光照相机把它们以叠加方式画到一张低分辨率的渲染目标上（屏幕的 1/2 到 1/4），底色是夜色 `#161B2C`。
- 再用一个全屏四边形，以正片叠底的方式把这张图盖到角色层之上。
- 自发光层在暗层之上，所以暗处也能看到妖物的眼睛。
- 叠加和正片叠底的实现（M1 已验证）：Bevy 0.20 的精灵只有普通混合，这里用 `ExtendedMaterial2d<ColorMaterial, 混合扩展>`，着色器沿用 Bevy 自带的，扩展只在 `specialize` 里改渲染管线的混合状态，不用自己写着色器。图集的每一帧做成一个带对应纹理坐标的四边形网格并缓存，同一页贴图、同一种颜色的共用一个材质，可以合批。
- 光照图是窗口分辨率的一半；窗口改变大小时跟着改。光照相机和主镜头同步，暗层是一个铺满镜头的四边形。
- 光源：灯笼（灯笼挂点，逐帧逐方向）、灯火、魂火（最多 200 个）、石灯笼（灯火挂点）、击杀闪光（0.3 秒，精英加倍）。颜色、半径照 docs/PORTING-NOTES.md 第 7 节。
- 辉光：主镜头开 HDR 和 Bevy 自带的 Bloom（叠加模式，阈值 1.0）；画在主画面上的自发光亮度乘 `EMIT_HDR`（1.5），叠起来超过 1 的部分才晕开，纸面和墨色不受影响。设置里可关。
- 光照图的底色平时是夜色，夜主登场时压暗，天明时 3 秒内变成晨光（`atmos.rs`，docs/FEEL.md 第 4 节）。暗层的大小按窗口比例当场计算，跟着主镜头缩放、侧倾。

### 9.2.1 近场受光与场景纵深（M2-12）

- **主角与夜主受光**：`lighting.rs` 的 `SurfaceMaterial` 使用嵌入式 `surface_light.wesl`，由裁边帧中心的球面法线混合 alpha 梯度法线；梯度采样钳在帧内，镜像时同步翻转法线。乘原图颜色后小幅叠加在角色同一深度，再经过原光照图，墨线、透明区和纸纹保留，不单独进入自发光层。线性增亮封顶 0.48；受击闪白的夜主暂不加受光，避免抢命中反馈。
- **主光预算**：固定三盏——逐帧手灯挂点、燃灯事件位置（0.55 秒回落）、离玩家最近的夜主狐火弹幕（与弹幕相同插值）。不遍历全部光源对每个妖物求光照；普通妖物继续用原精灵批次。受光实体/材质按槽复用，只有主角与在画面的夜主额外叠画。
- **接触阴影**：复用 `vfx/shadow` 和原精灵池，朝远离光源方向偏移，最大为脚底半径的 22%，两个轴各最多伸长 28%，保持贴地。悬浮妖物影子较淡。主角、夜主、地景选三盏主光中的最强者，普通妖物仅算手灯，光圈外直接返回静态影子。地景离屏不提交影子；所有接触阴影 z=9，低于地面预警。
- **狐祠庭院**：`ground.rs` 从局种子独立派生一处位置，在出生点侧前方；放大现有 `fox_shrine` 帧，组合石狐、狐灯、熄灭石灯、竹和山石。两侧落石/竹叶带及狐爪印引路，庭院与小径抑制随机散景，外缘平滑恢复密度。散点中不再重复放狐祠。图集二进制、碰撞、模拟状态和随机流均不变；带缩放道具的挂点、自发光、影子同步缩放。
- **前景框景**：`foreground.rs` 固定 8 束程序化竹枝，种子决定相位、尺度、镜像；视差速度为地面 1.24 倍，横纵周期接缝都在屏外。叶片网格带 1.2 单位透明裙边；每帧合为一个网格、一份材质，上下仅外侧 22% 高度显现。以整束包围圆避让玩家，近身 85 单位完全透明，再用 65 单位过渡；旋转跟随镜头，窗口缩放重算保护区。精简特效减到 4 束，天明淡去 35%。同时避让九尾扫、狐火雨和冲锋预警的包围区；复用预警遍历收集，最多 32 区，超出时整层前景退出。z=205，危险描边 z=240，前景不会把描边压暗。
- **确定性与生命周期**：布局只用 view 自己的 PCG 派生流；庭院/前景/受光槽随一局销毁，主光事件状态归零；地面块继续按坐标生成与卸载。测试覆盖布局复现、出生点留白、区块访问顺序无关、双轴视差、玩家/危险区避让（含预算溢出）与阴影偏移方向。

### 9.3 动画、镜头与特效

- **动画**：帧名形如 `hero/walk_SE_05`（第 15 节），开局前按名字查好“动作 × 方向 × 帧”的表，每帧不再查字符串。主角朝向带滞后（偏离扇区中心超过 22.5° + 0.12 弧度才切换）；走路动画按移动距离推进（`stride_units`），待机、闪避按时间推进；倒下时播放一次 death。妖物按 fps 播放、每只错开相位，朝向玩家时左右镜像，受击 0.08 秒内换白色剪影帧，浮空的上下浮动。
- **镜头**（`camera.rs`）：跟随插值后的玩家位置，移动方向上略微前瞻；创伤式震屏（平滑噪声，带一点侧倾）、方向冲击、只往里推的缩放冲击。顿帧和慢镜只调 `Time<Virtual>` 的速度，模拟照样逐步推进，不影响回放。各事件的参数见 docs/FEEL.md 第 2 节。
- **粒子**（`particles.rs`）：固定容量的 CPU 粒子池，不创建实体，每帧攒成绘制请求写进精灵池和发光池；贴图在启动时用代码画好，作为图集的一页（`AtlasDb::add_page`）。需要上万粒子时再考虑 GPU 粒子。
- **地面装饰**：用本局种子派生出画面专用的随机数，同一个种子每次看到的地面一样，但不消耗模拟的随机流。P0 只有青丘，通用的草和墨晕之外铺青丘的 `qq_` 装饰，偶尔摆石狐、狐灯；唯一狐祠另按庭院构图放置；发光道具的光色、光半径取素材 meta 的 `light_color`、`light_radius_units`，光放在 `glow` 挂点。以后有了地区，再按地区挑装饰。
- **法器与法术（M2）**：`fx.rs` 参照网页版 `render/weaponViews.ts`。持续存在的东西（飞剑、纸鹤、石印与预警、地裂、护盾、拾取物、夜主弹幕、奇遇道具）每帧直接读模拟资源，画进同一个精灵池；一次性的效果（各种环、印痕、连锁爆炸、太极、燃灯）收到 `SimEvent::Strike { fx, .. }` 等事件后记在 `FxState` 里自己计时淡出。装饰性的地面圆按透视压扁（×0.62）。夜主危险预警例外：`telegraphs.rs` 从模拟的 `DangerArea` 生成圆、扇形与弹道走廊，只做 `to_screen` 的 Y 翻转，不额外压扁或按贴图角度拉伸。显示的是玩家中心危险边界（已计入玩家碰撞半径），九尾扫与狐火雨的实际伤害、危险区特效压暗共用该几何。固定边界与蓄力描线分离，普通透明混合描边位于 `TELEGRAPH = 260`，在夜色、自发光和战斗粒子之上、伤害数字之下。
- **震屏与闪屏**：都在画面层，由事件触发（落印、地裂、燃灯、夜主登场、受伤），不影响模拟。
- **伤害数字**：96 个 `Text2d` 的环形池，按 28 号字栅格化后缩小到世界单位；普通数字按五行上色，暴击用毛笔字、金色、盖章式弹出。反应名在发生的地方飘出毛笔小字（12 个的环形池）。墨点（最多 160 个）和击杀闪光也在 `effects.rs`。
- **氛围**（`atmos.rs`）：萤火、夜雾、暗角（Bevy 的 `Vignette`，受伤和濒死时变化）、受伤时的色差、天明。

### 9.4 画质设置

设置菜单里提供：渲染分辨率比例、光照图精度、辉光开关、粒子密度、垂直同步、帧率上限，以及低、中、高三档预设。网页版的自动降画质是为手机设计的，桌面版默认不用；调试面板里保留开关。

目前做了：辉光开关；特效“完整 / 精简”（精简时粒子减半，不画萤火、夜雾和色散，见 `docs/FEEL.md` 第 7 节），设置里是 `lite_fx`，同步到画面层的 `Feel::lite`。

## 10. 音频（`lantern_audio`）

- **总线**（`mixer.rs`）：kira 0.12，音乐、音效、界面、环境四条用户总线，对应 `Settings::{music,sfx,ui,ambience}_volume`。音效总线下分三路：普通战斗（64 声部）和高光（32）共用一个压缩器；危险预警（16）是干声，不过压缩器也不带混响，繁忙战斗中仍有清楚的起音。音效保留 +7 dB 补偿（和网页版响度对齐），界面 +4 dB。音乐总线挂一个低通滤波器，暂停、升级、开宝箱时把截止频率压低，听起来变闷。设置即时生效，新增字段带默认值，旧 `settings.ron` 的音乐、音效设置不变。
- **空间**（`space.rs`、`ambience.rs`）：标题、灯驿、夜战、夜主各有一种混响（余响、阻尼、立体声宽度、湿声比例）和位置衰减，作为插入效果挂在音乐、战斗、高光、环境各轨上（不再用共用的混响发送轨），换场时 0.9 秒平滑过渡。混响在各轨音量之前，关掉总线或闪避时连尾音一起压下。界面和预警是干声。四段 12 秒的环境循环（标题的风、灯驿的灯芯、夜战的夜虫、夜主的低鸣）按单声道 16 位存，播放时右声道取 17 毫秒前的采样展开成立体声；循环头尾交叠，换场 1.2 秒交叉淡化。
- **高光闪避**（`duck.rs`）：整帧先收集事件，再按独立的保持／释放包络取最深衰减；燃灯、进化、夜主登场／换阶段／狂暴、濒死救回、共鸣、开宝箱、倒下结算让普通战斗声、音乐和环境声退后。高光本身、危险预警、界面反馈不闪避；夜主的出手预警几秒一次，也不触发闪避。夜主倒下（和天明仪式）时普通战斗、音乐、环境静 0.55 秒，清掉正在响的高光，低锣在 0.6 秒独立起音，天明的编钟晨鸟在 1.6 秒进入；天明仪式一局只办一次，小事件不会延长大事件的静默。设置音量与闪避逐帧合成，释放不覆盖玩家刚调的音量。返回标题／开局清除延迟音效、限频、闪避和低通状态。
- **乐器**（`synth.rs`）：把 `web/lantern/audio.js` 的合成算法（古筝式拨弦、编钟、太鼓、木鱼、锣、滤波噪声）移植成 Rust。增加箫式持续音；音效和环境声在启动时合成，音乐采样库由独立后台线程合成，主线程非阻塞接收；运行时只负责播放。低音持续音（drone）混入音乐底层。
- **音乐**（`music.rs`）：以八小节 E 角调青丘主题为骨架，原主题、变奏、对比、发展与再现组成 64 小节（约 183 秒）长曲式，详见 `FEEL.md` 第 6 节。`music/score.rs` 后台合成共享的 48 kHz/16 位单声道采样库；`music/playback.rs` 的六个 Kira 声源按采样位置轮转，六条分轨是音乐总线的子轨道，音乐音量、闪避、低通和场景混响都作用于它们；主线程每 0.2 秒采样战斗压力，探索/围攻按四小节、夜主登场按一小节切换，用一拍渐变配器。标题轻奏主题，天明在静默、低锣、晨钟演出后从头一次性完整播放；结算不截断，返回标题延至收句。调度与压力逻辑可脱离声卡测试。
- **内存**：常驻 PCM 约 98.3 MiB（音乐 58.59 MiB、音效 35.31 MiB、环境 4.40 MiB），`music/score.rs` 的测试把三者全部算上，限 120 MiB。
- **命中**（`impact.rs`、`sfx.rs`）：法器命中按法器（灯火、符剑、霜铃、纸鹤、山印）分组，普通／暴击各三种材质纹理，各有自己的限频键，一帧最多 8 个。音频私有的 PCG 洗牌轮换纹理，跨轮也不紧邻重复；音高 ±0.7 半音、力度 −1.5～+0.5 dB 随机。没有法器的命中（燃灯、爆炸等）只用通用命中声和暴击声，音高抖动取自同一条随机流，不叠第二套采样。不读取 `SimRng`，不拿帧时间取小数冒充随机。
- **音效**（`sfx.rs`、`lib.rs`）：把 `SimEvent` 映射到声音和声部（战斗、高光、预警、界面）。同类声音有最小间隔，连续拾取魂火时音高逐步升高，连斩、升级、进化、开宝箱（按稀有度三档）、夜主登场、夜主换阶段（狐啸）各有专门的声音。有位置的音效按相对主角的左右做声像、按远近衰减（距离按场所）；濒死时有心跳（docs/FEEL.md 第 6 节）。
- 音频只读模拟状态和事件，不影响模拟。启动时没有音频设备则记录警告并静音运行，之后按真实时间重试（`retry.rs`：先 3 秒，失败一次间隔翻倍，最长 15 秒；没有声卡的机器每次尝试系统音频库都会往终端打错误，所以不一直 3 秒一次。暂停或选择升级时也继续，长帧后不补发积压的重试；只在第一次失败时警告）。失败时插入 `lantern_platform::AudioUnavailable` 资源，界面在右下角显示“无音频设备”；恢复后重建总线、环境声和音乐（音乐从当前模式重新进入），移除资源并隐藏提示，不重放静音期间的音效。用户把音量调零不算设备不可用。
- **界面上的声音**：界面不依赖音频。界面上的演出和菜单操作不是模拟事件，由界面发一条 `lantern_platform::UiCue` 消息（`ScrollUnroll`、`ScrollLine(行号)`、`LampLit`、`DawnSpread`，菜单的 `Move`、`Confirm`、`Back`），音频照着播，都走界面总线：演出音同一帧来几个响几个，菜单音一帧只响最后一个、间隔至少 45 毫秒。标题界面此刻是标题还是灯驿（含里面的四处），界面写在 `lantern_platform::MenuSoundscape` 资源里，音频据此换混响和环境声。音频的系统在 `PostUpdate` 的 `AudioSystems` 里串行执行，界面在 `Update` 里已经写好；模拟的 `SimOutbox` 在 `Last` 清空。

## 11. 界面（`lantern_ui`）

- 用 `bevy_ui` 做：标题（出发、灯驿、设置、退出；跑分在“设置 → 高级”）、出发准备（通关一更后可选玩法：夜行或无尽夜，无尽夜只能选通关过的更；选更、择灯、挂灯坠、选悟、开关属性）、夜签选择、灯驿（老灯匠·心灯、货郎·属性、灯童·成就、说书人·图鉴，`hub.rs`；选中的人物说一句台词，由 `Profile::hub_dialogue` 按 `hub.ron` 的条件分档挑：没听过的追问（`ask: true`，灯童问青丘的几句，必须带 `once`）> 初见 First > 没听过的其他 `once` 台词（积累回应：`MetaLevels` / `MetaLevel` / `Runs` / `Wins` 里程碑必须有 once；留灯以后老灯匠、说书人的话也在这一档，不抢自我介绍）> 即时回应和持续状态（不带 once）> 轮着说“平时”，同档取满足的最后一条。once 是稳定 ID，同一个人的几句可共用（同一问的几种说法），不同人物不能共用；content 校验门槛、节点和故事事件引用。once 台词说出口（长卷画出选中那位的台词时）才由 `Profile::saw_hub` 记进存档的 `hub_lines_seen`，只记选中那位、存档有变才写盘；这一趟回灯驿里记在 `HubNews::heard`，照样说，重画不换句，下一趟不再说。“刚发生的事”记在不存档的 `HubNews` 里：结算时比较记进存档前后的变化，在灯驿里点亮心灯、退还属性时也记；`lit`（这次从 0 级点亮的心灯节点）、`dawn`（第一次天明的地区）、`road_lit`（这次归来新添的那盏路灯）给灯驿长卷的动画用，播完由画面清掉）、游戏中的信息栏（生命、经验、护盾、时间、击杀、连斩、燃灯、法器与心法栏、五行点数、夜主血条、增益）、升级三选一（重抽、跳过）、宝箱、进化展示、点灯奖励、货郎、灯坠三选一与替换、余烬的开局心法三选一、暂停（继续、音量、全屏、回到标题）、结算（新纪录、新成就）、提示条。第一夜之前灯驿锁着，出发直接开局（一更、红纸灯、不抽夜签）。
- **皮肤**：美术管线输出的九宫格贴图在 `assets/atlas/skin/`，`skin.json` 记录每张图的切边（左、上、右、下，按 2 倍绘制）。`skin.rs` 读它，`Skin::image(名字)` 返回切好边的 `ImageNode`。贴图画在边框盒上（`VisualBox::BorderBox`），不受内边距影响。卡片按稀有度换底，选中时叠一层高亮框。
- **导航**：没用 `bevy_input_focus`，每个界面自己记一个选中下标，读平台层的 `Actions`（方向键或十字键切换，回车或 A 键确定，数字键直选，R 重抽，X 跳过，Esc 返回）。鼠标悬停改选中项，点击等于确定。所有界面都可以不用鼠标操作。
- **小窗口与高 DPI**：标题面板和选择面板共用 `responsive.rs` 的画布，按窗口逻辑宽高计算 `min(宽 / 画布宽度, 高 / 画布高度, 1)`，扩大排版画布后用根节点 `UiTransform` 等比缩回窗口。默认画布为 1280×1080；出发准备按可见行数增加高度，每行预留 80，页头和页脚共预留 280，全部解锁时高 1400。心灯面板宽为画布的 90%、最大 1120，画布最小宽 960，高度按两列条目数预留，条目名称、等级和价格可换行。升级页按视口比例和卡片数量选择画布尺寸，优先保持较大字号；卡片区域宽 90%，卡片宽 256（`responsive::CARD_WIDTH`，卡片内部排版见 #10 的 `choice.rs`），窄窗口允许换行；页头和底部提示也限制宽度。窗口调整、跨屏 DPI 变化和全屏切换都在布局前更新，不重复除以系统缩放，不设导致小窗口溢出的最小比例。缩放只作用于这些面板，点击区域随节点变换；开场卷轴继续用自己的视口百分比布局。
  - 自动回归：`cargo test -p lantern_ui`，纯函数覆盖 150% / 200% DPI、1280×720、1024×768、960×540、800×600、640×360、窄窗口换行、窗口恢复和无可用尺寸；无窗口排版测试使用真实字体、心灯条目和含共鸣及封印提示的四张升级卡。
  - 人工验收：Windows 设置 150% / 200%，打开主菜单、心灯、全部属性已解锁的出发准备，以及含四张卡和封印提示的升级页；缩小窗口至上述逻辑尺寸，再跨不同 DPI 显示器拖动并按 F11 切换全屏。确认面板、卡片、操作提示完整可见，鼠标悬停与点击位置正确，方向键和数字键选择正常。
- **只读模拟**：升级卡片、宝箱、结算都只读 `Flow`、`Build`、`Arsenal` 等资源，玩家的选择发 `SimCommand::Choose / Reroll / Skip / Ack`。卡片上的说明文字（升级前后的数值、新心法、进化）由 `describe.rs` 根据内容数据生成。
- 字体：标题用 Ma Shan Zheng，正文和数字用 Noto Serif SC（都是 OFL 协议）。`crates/ui/fonts.py` 裁剪出子集：GB2312 一级字库的 3755 个常用汉字，加上界面代码和 `assets/data/` 里所有非 ASCII 字符（两款合计约 4.6 MB，完整字体约 31 MB）。常用字预先放进去，新增文字大多不用重新生成，各个分支也不会老在这几个二进制文件上冲突；用到常用字以外的字时 CI 的 `--check` 会报缺字，再运行一次脚本。Ma Shan Zheng 没有“·”，标题字体的文字里自动换成“•”。
- 文字：界面固定文字仍写在 `crates/ui` 的代码里，名字和说明在 `assets/data/`。加第二种语言时再统一移到 `assets/i18n/`（第 8 节）。
- 性能面板默认隐藏，仅开发模式或“设置 → 高级 → 性能调试”开启后可用 F3 切换；种子号也只在面板内显示。面板包含：帧率、帧时间、模拟每步耗时（FixedUpdate 首尾计时，只做诊断）、画面层每帧耗时（`ViewStats`）、妖物和魂火数量、精灵、发光与粒子数量。egui 调试面板（实时开关光照、调整妖物数量、无敌、加速）在需要时再加，只在 `dev` 特性下编译。
- **灯驿长卷**（`ui/hub_scene.rs`，素材和 `hub.json` 格式见第 15 节）：灯驿和它下面四处铺美术的长卷，代替标题画。长卷的节点只在进出灯驿时建、拆：底图、远山晨光（通关过的地区；`HubDawn`，Image 层默认是普通图，`hub_fx` 要铺开时换成 `DawnReveal` 材质，灰度图路径在 `HubDawnMask`）、12 盏心灯（等级 > 0 才亮；`HubLamp` 分 body、flame、core、glow 四层，火苗带 `HubFlameBase`，光晕亮度按“等级 ÷ 最大等级”；每层的贴图路径在 `HubImage`）、门外 10 盏路灯（`hub.json` 的 `road_lamps`，回来几回点几盏、十盏为止，`Profile::road_lamps`；`HubRoadLamp { index, part, lit }` 同样分四层、火苗带 `HubFlameBase`、贴图路径在 `HubImage`，没点到的隐藏；这次归来新添的那盏在 `HubNews::road_lit`，点亮动画由质感会话在 `hub_fx` 里接）、人物的聚光（`HubLight`，选中的人亮）和点击区。叠加层用 `UiAdd` 材质（`ui_add.wesl`，画面 += 贴图 × alpha）。名牌、底部那条里选中人物的台词和操作提示、左上角的“灯驿”和钱袋是界面面板，按长卷当前的缩放换算位置，选中项或窗口大小变了就重画；放字的矩形夹在窗口里。打开子面板时压暗 60% 再盖纸面板。没有 `hub.json` 时退回卡片界面。
- 整幅的画（标题画，灯驿长卷）按“铺满再居中裁边”铺（`ui/cover.rs`）：缩放 s = max(窗口宽 ÷ 画宽, 窗口高 ÷ 画高)，居中，超出窗口的部分裁掉，不拉伸、不留黑边；画在上面的东西都过同一个变换。
- **开场卷轴**（`ui/scroll.rs`，docs/GAMEPLAY.md 第 2.5 节）：出发时如果这个地区的卷轴还没展开过，先在标题界面展开：画是 `atlas/screens/scroll_<地区>.png`，从左往右展开，左上角的天空里一行行浮出 `regions.ron` 的旁白（长夜版纸色字）；确认、返回或点一下就接着出发。拿回烛火（通关过一更）以后再出发，展开一次天明版 `scroll_<地区>_dawn.png`（墨色字，数据里写了天明旁白才展开）。展开过的记在存档的 `scrolls`。
- 跑分仅受妖物池容量限制，正常游戏仍受内容里的硬上限限制；预热未达到目标时明确失败。呈现帧时间使用 `Time<Real>`，模拟每步耗时单独测量。
- 跑分（设置 → 高级 → 性能跑分）：依次保持 250、1000、2500、5000 只妖物，各 10 秒（前 3 秒不计），主角无敌、自动绕圈；结束后显示结果，并存到数据目录的 `bench/bench-<时间>.txt`，内容包括显卡、窗口大小、每段的帧率、95% 帧时间、最长帧和模拟耗时。

## 12. 平台（`lantern_platform`）

**输入**：`platform/input.rs` 在 `PreUpdate` 汇总 `Actions`。默认键盘 WASD / 方向键移动、空格 / Shift 闪避、E / F 燃灯、G 交互（狐村护火、留灯）、Esc 暂停；手柄左摇杆 / 十字键移动、A / RB 闪避、Y / RT 燃灯、X 交互、Start 暂停。交互（`Action::Interact`）只属于“游戏进行中”场景，和菜单里的跳过、灯驿（也是手柄 X）不冲突，提示模板写 `{interact}`。模拟只在 `SimPhase::Play` 接收量化的 `InputFrame` 与 `SimCommand`，玩法和回放格式不变。

- **菜单导航**：标题、设置、暂停、结算、灯驿、夜签、升级、点灯、货郎、灯坠均支持手柄。摇杆移动死区 0.22，菜单触发 / 回中阈值 0.55 / 0.30；只走主轴，长按先等待 0.34 秒，再每 0.11 秒走一格。网格按视觉行列循环，货郎跳过不可购买项。升级用上下切换卡片与重抽 / 封印 / 跳过操作，保留封印目标。焦点沿用泥金框；鼠标只有实际移动或点击才接管。
- **设备提示**：`ActiveInput` 记录最近有效的键鼠 / 手柄操作；摇杆漂移、保持杆位不抢走另一设备，断开手柄回到键鼠。`ui/prompts.rs` 的 `Prompt` 模板在 UI 布局前按当前绑定展开，覆盖 HUD、菜单、燃灯提示与回放；切设备不重建面板、不重播动画。面键用位置约定 A 下、B 右、X 左、Y 上。
- **改键**：标题设置和暂停设置共用 `ui/controls.rs`；键盘四向及动作、手柄动作可改，十字键 / 摇杆导航固定。`Bindings` 按场景检测冲突，保留键盘方向键 / Esc、数字直选与系统快捷键。冲突不覆盖原绑定；捕获前后均等松键，捕获按键不会穿透菜单或模拟。旧副键仅在动作未改键且未被自定义绑定占用时保留。每页可恢复默认，改动立即原子写入设置。
- **首夜引导**：`ui/onboarding.rs` 在首个正常夜行显示移动、闪避、燃灯、升级的非模态轻提示；移动读取实际位移，闪避 / 燃灯读取 `SimOutbox`，升级核对模拟接受前后的选择阶段。每项完成即保存，完整完成后不再出现；第一局结算后也不再提示。放弃首局再出发时只补未完成项。每个情境最多显示十秒，暂停和无关选择页隐藏，跑分 / 回放 / 自动驾驶 / 无敌模式不写教学进度。引导只读模拟状态，不改模拟命令、随机流或结果。

界面读取平台层的 `InputDevice`，按最近一次有效键鼠或手柄输入切换战斗提示；忽略键盘连发、松键与轻微摇杆漂移，不改动模拟输入。底部操作提示与生命、燃灯条共用纵向布局，边缘指示图标避开该区域的实际高度；提示只在正常战斗时显示，暂停、选择、死亡与结算时隐藏。

**数据目录**（通过 `directories` 获取）：
- Linux：`~/.local/share/lantern/`
- Windows：`%APPDATA%\lantern\data\`

| 文件 | 内容 |
| --- | --- |
| `save.ron` | 局外进度（`Profile`，第 3 版）：灯油和铜钱（余额、累计）、心灯等级、局外属性等级与开关、解锁的灯和灯坠、开放到第几更、成就、见过的反应、上次的选择（含是否走无尽夜）、见过的灯驿人物、展开过的开场卷轴（`scrolls`）、最佳记录、无尽夜各更的最长存活（`endless`）、累计统计、局数和胜场、首夜教学完成项（`onboarding`）、已见故事事件（`events: BTreeSet<String>`）、已拾手记（`journals: BTreeSet<u8>`）、灯驿里听过的只说一次的台词（`hub_lines_seen`，`hub.ron` 的 once ID） |
| `settings.ron` | 第 2 版：全屏、垂直同步、音乐／音效／界面／环境音量、画面手感选项、键盘与手柄动作绑定（`bindings`） |
| `replays/` | 最近 20 局的回放 |
| `logs/`（Windows 见下文） | 运行日志（保留最近 5 份），包含 panic 信息与调用栈 |
| `crash/`（待实现） | 独立崩溃报告与当局回放 |

**日志与致命错误**：主程序进入 `main` 后，先调用 `platform::diagnostics::init`，再解析参数、加载内容和构建插件；禁用默认 `LogPlugin`，由平台层统一记录 Bevy 与游戏日志。Windows 日志单独放在 `%APPDATA%\lantern\logs\`，Linux 放在数据目录的 `logs/`；每次启动新建 `lantern-<时间戳>-<进程号>.log`。普通日志遵循 `RUST_LOG`，启动标记、致命错误和 panic 不受过滤影响，直接写入并同步到文件。panic 记录位置、线程和调用栈；Windows 通过原生错误对话框展示原因与日志路径，日志目录建不了（只读、权限、被占用）不挡住游戏：警告后只写终端，之后的致命错误提示里写明“日志尚未建立”和日志目录。参数、内容或回放加载失败统一调用平台层的 `fatal`；图集加载失败时携带具体路径和原因触发 panic，交给同一诊断入口记录并提示玩家，同时停止依赖图集的初始化链，避免帧末退出前继续运行导致缺资源错误。画面层不依赖平台层。

- 存档和设置都带 `version` 字段，每次升级格式时写一个迁移函数，旧存档逐级迁移。主文件不可用时读取并解析 `.bak`；恢复成功后先保留损坏的主文件，再允许保存。主文件及备份都不存在才视为首次运行；恢复失败或无法安全保留原文件时暂用默认值/备份，并禁止保存覆盖原数据。
- 一局结束时结算界面调用 `Profile::record`：加灯油和铜钱、更新统计和最佳记录（无尽夜只记在它自己的榜上，按更分开）、判断成就并立即发奖（成就发的灯油和铜钱不乘倍率）；看回放、跑分、无敌模式不计。心灯、属性在标题界面（M2.5-4 起是灯驿）花钱升级，开局时写进 `RunSetup`，所以回放能重现。属性可以全部退还（返还实际花掉的铜钱），也可以出发前单独关掉。
- **第三版叙事存档**：`events` / `journals` / `hub_lines_seen` 与 `onboarding` 同在第 3 版，默认空集合，旧一、二版可加载，升版不补写玩家未做过的选择，也不补记听过哪句；余额和心灯等级原样保留，不按新价追补或扣回。`Profile::run_setup` 冻结 `StorySeed { events, journals, chapter }` 写入可选的 `RunSetup.story`，回放携带同一快照；`RunSetup::new` 缺省 `None`，旧回放、工具与基准路径不启用故事、不多取随机数。
- **故事模拟**（`sim/story.rs`）：35 秒保底故事点、6 秒护火、3 秒留灯、64 单位范围；`SimCommand::Interact`（平台动作 `Action::Interact`，只在游戏进行中生效，默认 G / 手柄 X，可改键）主动开始，走出范围取消本次计时。`StoryBeat { beat }` 和 `JournalFound { page }` 进入 `SimOutbox`。结算的 `RunResult.events/journals` 合并进 Profile，失败也保留，回放/跑分/无敌不写存档。所有叙事状态（含位置、计时、已拾页及初始快照）仅在启用时进入状态哈希，不改变旧默认黄金路径。
- **手记门槛**：卷一初始；卷二曾进入青丘或已有一夜记录；卷三通关一更或亲手留灯；卷四通关且完成至少 4 夜、持有至少 12 页；卷五通关且至少 6 夜、持有至少 18 页、心灯累计 6 级、无尽夜至少存活 900 秒并打退过夜主。章节在出发时固定，局内留灯仅能抬到卷三。普通掉落每夜首次点灯/古灯/血祭坛/货郎必得，之后 35% 概率且每夜最多三页，走 `SimRng` 的 Story 流（`Stream::Story`，加在流表末尾；只在叙事启用时写进状态哈希）。先补最早尚未集齐的已解锁卷，卷内随机未持有页；第 13 页在留灯时必得，或卷三开放后的首次有效拾取保底，不占概率。
- **内容与阅读**：`journals.ron` 存 30 页正文和卷三谜语，校验完整覆盖 1–30、无重复、无空正文、谜语卷次；纯文字不计内容哈希。`HubWhen` 增加 `Story`、`WithoutStory`、`JournalCount`、`HasCleared`、`All`，递归校验条件及故事 ID（`STORY_EVENTS` 只列模拟记下的事件）。灯童的追问是带 `once` 的台词（第 11 节），未听过的排在 First 前面；追问按亲历互斥，倒下回来也回应，不倒退补播旧阶段。说书人与结算共用 `ui/journals.rs`，页签、正文与翻页范围都只含已开放卷的已拾页，灯驿键（`Action::Hub`，默认 M / 手柄 X）打开，方向键翻页，返回或确定合上。
- **M2 存档迁移**（docs/BALANCE.md 第 10.6 节）：读到第 1 版存档时，内容加载好后由 `Profile::upgrade` 迁移一次——锋芒、体魄、灵巧清零并退回灯油，祈福保留等级，铜钱从 0 开始，按局数和胜场补发前 3 个成就。
- **M1 输入迁移**：旧设置缺少绑定时补默认值；手改产生冲突时仅恢复有冲突的设备。第 1 / 2 版存档迁到第 3 版，有已结算局数或已开放灯驿的老玩家直接标记教学完成，未开局存档保留首夜引导。
- 写入时先写临时文件，再改名替换，并保留上一份备份。断电或崩溃不会把存档写坏。
- 以后接 Steam 时，用 `steam` 特性开关 `steamworks`，负责成就和云存档，默认不编译。

## 14. 构建与发布

**编译配置**：
- `dev`：自己的代码用 `opt-level = 1`，依赖用 `opt-level = 3`（Bevy 官方建议）。Linux 上可以开 `bevy/dynamic_linking` 加快增量编译。
- `release`：`lto = "thin"`、`codegen-units = 1`、`strip = true`。
- Windows 发布版不弹出控制台窗口；EXE 内嵌图标、版本信息和清单（`game/build.rs`，`asInvoker`、`PerMonitorV2`），窗口和任务栏图标由 `platform` 的 `window_icon.rs` 从 EXE 资源读取。

**资源目录**：游戏启动时只调用一次 `platform::paths::asset_dir`，得到规范化的绝对路径（Linux 用 `canonicalize`；Windows 用 `std::path::absolute`，因为 `canonicalize` 返回 `\\?\` 开头的路径，里面的 `/` 不算分隔符，Bevy 拼上 `atlas/…` 就找不到文件）。内容数据、Bevy 的贴图与字体、图集 JSON、界面皮肤 JSON 全部复用这个根目录（图集与皮肤共用 `view::AssetRoot`），不再各自查找。
- 设了 `LANTERN_ASSETS` 就只用它（相对路径以工作目录为基准）；无效就报错，不静默换资源。
- 否则依次检查 EXE 旁的 `assets/`（发布包）、`CARGO_MANIFEST_DIR/../../assets/`（运行时有这个环境变量，即 `cargo run`，含 `--release`）。
- 开发构建（有 `debug_assertions` 或启用 `dev`）另外回退到编译时平台 crate 对应的仓库目录和工作目录的 `assets/`。发布版直接启动时不看工作目录，也不搜索 EXE 的祖先目录。
- 候选根目录必须存在且包含 `data/` 子目录。全部找不到时，在创建窗口前通过 `fatal` 报错，列出尝试过的绝对路径及失败原因并写入日志；具体内容与图集格式仍由各自加载器校验。
Bevy 0.20 的 `AssetPlugin.file_path` 必须是 `String`；资源目录无法无损转换为 UTF-8 时，在读取内容数据和创建窗口前调用 `fatal` 报错并写日志，不替换路径字符。资源目录编码错误及回放读取失败的诊断用转义形式保留非法编码，普通中文和空格路径不受影响。

**CI（`ci.yml`）**：桌面版相关的路径有改动时运行。
- Linux：`fmt`、`clippy -D warnings`、`test`。
- Windows：`test`，主要为了跨平台确定性的黄金测试。

**发布（`release.yml`）**：推送 `v*` 标签时运行。
- Linux：在较旧的 Ubuntu 上构建，兼容更多发行版的 glibc，产物为 `lantern-<版本>-linux-x86_64.tar.gz`。
- Windows：用 MSVC 构建，产物为 `lantern-<版本>-windows-x86_64.zip`。
- 两个包都上传到 GitHub Releases。
- 以后再加 AppImage、Windows 安装程序、Steam 上传。

**网页站点**：`pages.yml` 只在 `web/` 有改动时运行，桌面版的提交不会触发网页部署。仓库的 Pages 来源是“GitHub Actions”。

- `art/` 从 `lantern-next/art/` 移到了仓库根目录，命令在仓库根目录执行。
- **出图密度**：桌面版用 `LANTERN_ART_DENSITY=2`，即 **4 像素 / 世界单位**（网页版是 2）。视野高 420 个世界单位，1440p 下每个世界单位约 3.4 像素，略微缩小显示。中间产物在 `art/out/assets@2x/`，打包后放到 `assets/atlas/`。`web/lantern-next/public/assets/` 保持 1 倍密度，不再更新。

- **图集格式**：TexturePacker hash 格式 JSON + PNG（直通 alpha，未预乘，颜色已扩散到透明像素）。每帧有：
  - `frame`：在图集页里的矩形；
  - `sourceSize`：原图尺寸；`spriteSourceSize`：裁掉透明边后剩下的部分在原图里的位置和大小；
  - `anchor`：相对原图尺寸的锚点。角色和小妖 `(0.5, 0.875)`，石妖、精英、夜主、场景道具 `(0.5, 0.8)`；特效多为 `(0.5, 0.5)`。
- **`meta.lantern`**（每页都有）：
  - `pxPerUnit`：这张图集的密度。精灵的世界尺寸 = 像素尺寸 ÷ `pxPerUnit`，Rust 端不要写死。
  - `page`、`pages`：页号和总页数。多页时文件名是 `<图集>_<页号>.json/png`，`meta.related_multi_packs` 列出其他页；单页时就是 `<图集>.json/png`。
  - `frames`：本页每帧的 `{"blend": "normal" | "add", "tint": bool}`。`tint: true` 的帧是白色或灰度的，用时乘颜色；`blend: add` 的帧画在叠加层。特效、地面、界面帧还可能带素材 meta 里的其他标量字段，例如 `radius_px`（反应区域、扇形的半径）、`angle_deg`、`flat`、`stretch`、`width_px`，界面帧带 `kind`、`id`、`name`。像素单位都是本图集的像素，换算到世界单位除以 `pxPerUnit`。这些字段都是可选的，读取时不认识的字段忽略即可。
  - `assets`（只在第 0 页）：每个角色素材的 `meta.json` 原样保留（妖物只有 E 方向，道具只有 `idle` 的 S 方向 1 帧），包括 `size`、`anchor`、`px_per_unit`、`anims`（每个动画的 `frames`、`fps`、`dirs`、`loop`、`stride_units`、`windup_frames`、`loop_from`，见下面“妖物动作”）、逐帧挂点 `sockets`（单位是图集像素，相对锚点即脚底，x 向右、y 向下；换算到世界单位同样除以 `pxPerUnit`），以及 `shadow_radius_px`、`floating`、`category`（hero / enemy / elite / prop）、`anchor_kind`、`vertical_motion` 等。挂点：主角 `lantern`，妖物 `eyes`（竹魅另有 `muzzle`），石灯笼、古灯和货郎担 `flame`，血祭坛、狐仙祠 `glow`，狐灯 `glow` 和 `glow_0..2`。`game_radius` 只用来对齐画面，碰撞半径以 `assets/data/` 的妖物数据为准。`floating: true` 表示悬浮的妖物（影妖、疾影、狐火），游戏里给它们加上下起伏；`register_x_only` 只给美术自检用，可以忽略。
- **动画序列**：`animations`（只在第 0 页）把 `<素材>/<动画>_<方向>` 映射到有序的帧名列表；`_flash`、`_emit` 各有自己的序列，例如 `hero/walk_E_emit`。多页时帧可能落在任何一页，加载时先合并所有页的 `frames`。
- **帧名与方向**：
  - 帧名形如 `<素材>/<动画>_<方向>_<两位帧号>`，例如 `hero/walk_SE_05`；
  - 白色剪影帧（受击闪白）加 `_flash`，自发光层加 `_emit`，例如 `shade/float_E_03_emit`；
  - 方向依次为 `E SE S SW W NW N NE`，y 轴向下；
  - 妖物只画 E 方向，往西走时左右镜像；主角 8 个方向都有，不镜像（灯笼始终在右手）。
- **白色剪影帧**：`_flash` 是纯白剪影，尺寸、锚点和普通帧相同。受击时整帧换成它（普通混合），不是叠加。主角没有剪影帧。
- **自发光层**：`_emit` 帧和对应的普通帧尺寸、锚点完全相同，叠加画在暗层之上，所以暗处也能看到灯笼窗、妖眼。没有自发光部件的素材没有 `_emit` 帧。
- **主角动画**：`idle`（6 帧）、`walk`（8 帧，按移动距离推进，`stride_units` 是一个循环走过的世界距离）、`dash`（4 帧 @16 fps）、`hurt`（2 帧 @10 fps）、`death`（6 帧 @8 fps，不循环），各 8 个方向。主角帧里只有灯杖，没有灯笼头，也没有 `_emit`。
- **灯笼叠层**（一位主角，换灯只换叠层）：
  - 每盏灯一套和主角帧**同画布、同锚点**的逐帧叠层：`lantern_<灯>/<动画>_<方向>_<帧号>`，以及 `_emit`（灯芯，叠加）。动画、方向、帧数和 `hero` 完全一致。
  - 渲染时主角身体和灯杖当遮挡，被挡住的部分已经是透明的。所以游戏在主角帧之上原样叠画即可（同位置、同锚点，z 略高于主角），不用处理前后关系。
  - 灯的 id 和 `assets/data/lamps.ron` 一致：目前有 `red`（红纸灯）、`mirror`（铜镜灯）、`frost`（霜瓷灯）。以后的灯照同样规则加帧，id 以 lamps.ron 为准。没有灯笼的灯（无灯）什么都不画，不要回退到红纸灯。
  - 叠层的 `meta.lantern.assets.lantern_<灯>` 有 `category: "overlay"`、`base: "hero"`、`lamp`、`lamp_name`、`light_color`（与 lamps.ron 的 color 一致，以内容数据为准）。主角的 `assets.hero.overlays` 列出现有的叠层。
  - 灯光位置照旧用主角的 `lantern` 挂点。铜镜灯的铜镜在灯芯后面当反光镜，背面朝向（N、NE、NW）时灯芯被挡住，`_emit` 帧接近全透明，属正常现象，光源照常放。
  - 倒地动画里灯笼落在地上，灯芯渐暗，三盏灯一致。
- **宣纸**：不透明 RGB PNG，1024×1024，无缝平铺，1 纹素 = 0.25 世界单位（一张覆盖 256 个世界单位）。

  - 清单格式：`{"scale": 2, "items": {"<名字>": {"file", "size": [w, h], "slice": [左, 上, 右, 下], "center": "stretch"|"tile", "sides": "stretch"|"tile", "text": "#rrggbb", "note": "用途"}}}`。`slice` 全 0 的是固定尺寸的图（槽位、圆点、箭头），不切；`text` 是建议的文字颜色；`arrow_marker` 另有 `"tint": true`（白色，按奇遇颜色染）。
  - `scale: 2`：按 1080p 逻辑像素的 2 倍画。用 `TextureSlicer` 时设 `max_corner_scale = 0.5`；`tile` 的区域用 `SliceScaleMode::Tile { stretch_value: 0.5 }`。
  - Bevy 0.20 里要设 `ImageNode.visual_box = BorderBox`，贴图才画满整个边框盒；不设的话会缩进内边距里。
  - 只横向拉伸的条状元素（按钮、条、提示），节点高度不要超过贴图高度的一半（逻辑像素：按钮 56、血条 14、提示 36 / 44），否则两端会被竖着拉伸。
  - 内容：
    - 面板 `panel`（宣纸，毛边）、`panel_dark`（夜色墨底）、`overlay_vignette`（全屏暗角，整张拉伸）；
    - 卡片 `card_{fan,ling,xuan,tian}`（品级色墨框，天品带金晕）、`card_omen`（夜签，朱砂框）、`card_focus`（焦点高亮，叠在卡片上，切法相同）、`note_box`、`note_box_hi`；
    - 按钮 `btn`、`btn_primary`（朱砂），各带 `_focus`、`_pressed`、`_disabled`；`pill`、`pill_on`；
    - 槽位 `slot_l`（法器 128²）、`slot_s`（心法 80²），各带 `_empty`、`_evo`；
    - 条 `bar_track`、`bar_fill_{hp,xp,boss,shield,unlock}`（填充按百分比设宽度，任何宽度都正常）、`pip`、`pip_on`（心灯进度点）；
    - 提示 `toast`、`toast_big`、`chip`、`chip_dark`；
    - 其他 `divider`、`scroll_body` + `scroll_end`（宝箱卷轴，另一端镜像）、`arrow_marker`（屏外奇遇指示，尖角朝 +X，代码旋转）、`focus_ring`（键盘 / 手柄焦点）、`menu_hl`（标题菜单选中项的底）。

## 16. 性能预算

| 项目 | 目标 |
| --- | --- |
| 最低配置 | 集成显卡（Intel UHD 620 一级）、4 核 CPU、1080p、中画质：2000 只妖物加 150 个光源，60 fps |

| 模拟 | 5000 只妖物每一步 ≤ 2 ms（在云端这台 4 核 2.1 GHz 的机器上测量）。M1 实测：1000 只 0.57 ms，2500 只 0.57 ms，5000 只 0.95 ms（95% 分位 1.19 ms）。M2 加上全部玩法后 5000 只 0.79 ms |
| 每帧预算（16.6 ms） | 模拟 ≤ 3 ms，画面层 CPU ≤ 4 ms，GPU ≤ 8 ms |
| 其他 | 内存 < 500 MB，安装包 < 150 MB，启动到标题界面 < 3 秒 |

## 18. 风险

| 风险 | 应对 |
| --- | --- |
| Bevy 每隔几个月就有不兼容的更新 | 锁定 `=0.20.0`；只在里程碑之间升级；少用第三方 Bevy 插件；模拟层只依赖 ECS，这部分 API 相对稳定 |
| Rust 编译慢 | 调整 dev 配置，开动态链接；CI 缓存 `target/` |
| 云端没有显卡，看不到真实画面 | 用 lavapipe 截图做冒烟测试；观感和帧率以你本机为准；调试面板和跑分结果卡可以一键复制，方便反馈 |
| 跨平台浮点结果不一致，回放失效 | 用 `libm` 计算超越函数，clippy 禁用 `std` 的浮点数学方法，黄金测试在两个平台上对照 |
| Linux 发行版差异 | 在较旧的 Ubuntu 上构建；同时支持 Wayland 和 X11；发布说明里列出依赖（ALSA、udev、Vulkan 驱动） |
| 两个会话同时修改仓库 | 按目录分工（第 19 节），推送前先 `git pull --rebase` |
