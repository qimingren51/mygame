# 提灯夜行 · 桌面版架构设计

> 状态：M2 完成（2026-10-12）。目标平台先做 Linux 和 Windows，技术栈为 Rust + Bevy。
> 玩法与数值设计见 `docs/GAMEPLAY.md` 和 `docs/BALANCE.md`，世界观与命名见 `docs/LORE.md`。M2 照搬网页版（`web/lantern/DESIGN.md`、`docs/PORTING-NOTES.md`）作为平衡基线，M2.5 起按这几份文档改。本文只讲技术架构。

## 1. 目标

| 目标 | 具体要求 |
| --- | --- |
| 模块化、易扩展 | 新增一个法器、妖物、夜签、奇遇，主要是加一份数据和图集帧。只有出现新行为时才写一个新系统，而且不改动已有模块。 |
| 性能 | 桌面上 5000 只妖物、400 个光源，稳定 60 fps（指标见第 16 节）。网页版的目标是 1000 只。 |
| 可复现 | 同一个种子加同一串输入，结果完全一样，Linux 和 Windows 之间也一样。回放、自动化测试、平衡模拟、错误复现都建立在这一点上。 |
| 不开窗口也能运行 | 模拟层不依赖窗口和显卡，可以在云端容器里跑测试、跑分、批量模拟。 |
| 可发布 | GitHub Actions 打出 Linux 和 Windows 安装包。以后可以接 Steam，也可以加 macOS 和 Steam Deck。 |

不在本阶段做的：联机、网页版、手机版、Mod 加载器（但数据格式按以后可以开放给 Mod 来设计）。

## 2. 技术选型

| 部分 | 选择 | 说明 |
| --- | --- | --- |
| 语言 | Rust 1.97（stable，edition 2024） | `rust-toolchain.toml` 锁定版本 |
| 引擎 | Bevy `=0.20.0` | 锁定精确版本，只在里程碑之间有计划地升级；关掉默认特性，只开 2D 需要的部分 |
| 数学 | `bevy_math`，开启 `libm` 特性 | 三角函数、指数函数走纯 Rust 实现，保证跨平台结果一致（第 7 节） |
| 数据格式 | RON（`serde` + `ron 0.12`） | 内容数据、存档、设置都用它，人和 AI 都容易读写 |
| 音频 | `kira 0.12`，直接使用 | 支持混音总线、滤波、精确到采样的时钟，音乐音序器需要这个。不经过 Bevy 插件，升级 Bevy 时少一个要等的依赖 |
| 调试界面 | `bevy_egui 0.43` | 只在 `dev` 特性下编译，发布版不包含 |
| 存档路径 | `directories 6` | 按各系统的规范目录存放 |
| 随机数 | 自己实现 PCG32，不依赖 `rand` | 算法不随依赖升级而变化，旧回放永远能重放 |
| 测试 | `cargo test`，`criterion 0.8` 做性能基准 | |
| 美术 | 沿用 Blender 无头渲染加 Pillow/numpy 后期（`art/`） | 只改输出目录 |

第三方 Bevy 插件尽量少用。插件通常要晚几周到几个月才支持新版 Bevy（例如 `leafwing-input-manager` 写这份文档时还停在 0.19），每多一个插件，升级时就多一个等待项。输入映射、图集加载、粒子都自己写，代码量不大。

## 4. 分层与依赖规则

```
game（可执行程序，只做组装）
 ├─▶ ui ─────▶ platform
 ├─▶ view
 ├─▶ audio
 └─▶ platform
        │  ui、view、audio、platform 都依赖 ▼
       sim ─▶ content ─▶ core

tools（命令行，不开窗口）─▶ sim、content、core
```

- 依赖只能向下（`ui` 另外依赖 `platform`，用来读取抽象操作）。`sim` 的 `Cargo.toml` 里只有 `bevy_app`、`bevy_ecs`、`bevy_math`、`bevy_state` 这几个子 crate，根本链接不到渲染、窗口和音频代码。分层由编译器保证，不再靠测试去扫描源码。
- `view`、`audio`、`ui` 只读模拟状态，再加上消费模拟发出的事件（第 6.7 节）；改变模拟的唯一方式是发送命令。
- 每个 crate 对外只暴露一个 Bevy 插件，例如 `SimPlugin`、`ViewPlugin`，再加上少量公开类型。`game` 只负责把插件组装起来，本身不写逻辑。

## 5. 主循环与状态机

**时间**：模拟在 Bevy 的 `FixedUpdate` 里运行，固定每秒 60 步，步长用常量 `1/60`，不读取真实时间。画面在 `Update` 里运行，用 `Time<Fixed>` 的超出比例在上一步和这一步之间插值。一帧最多补 4 步，卡顿时宁可让游戏变慢，也不让模拟连续追赶。

**状态**：

```
AppState:  Boot → Title（含灯驿、出发准备、夜签三选一、设置）→ Run → Title
RunState（Run 的子状态，只管界面）:  Playing ⇄ Paused，Playing → Over（结算）
SimPhase（模拟内部的资源）:  Play ⇄ LevelUp / Chest / Evolve / Lantern / Shop / Charm，Play → Over
```

- 一局之内的阶段 `SimPhase` 放在模拟里，**不用 Bevy 的 State**（M2 实现时改的决定）：State 要到下一帧开头才切换，一帧里补跑几步时，升级之后还会多跑几步，实际游戏和不开窗口的重放就对不上了。
- 每步开头记下这一步是否处于 Play（`StepGate`）。不是 Play 时只跑 Input：处理界面发来的 `Choose(i)`、`Reroll`、`Skip`、`Ack`，游戏时间不走。所以“选了什么”也被回放记录下来。
- 升级选项、宝箱内容由模拟生成（“选项”“宝箱”随机流），界面只负责展示和发命令。暂停（`RunState::Paused`）不属于模拟，暂停时 `FixedUpdate` 整个不跑，也不进回放。
- 开局前的夜签三选一在标题界面完成：用本局种子派生的“夜签”随机流抽 3 张。选定的夜签，连同心灯等级、生效的局外属性、灯、出发前挂的灯坠、已解锁的灯坠、更、悟·五行，一起写进 `RunSetup`（`Profile::run_setup` 拼出来），回放文件头里存的就是它。
- 局内的选择阶段排队打开，顺序是：进化演出 → 升级 → 宝箱 → 点灯奖励 → 灯坠三选一。灯坠栏满了时，`Choose(i)` 先选新的一枚，再 `Choose(j)` 选换下哪一枚；`Skip` 在替换时返回、在三选一时放弃。

## 6. 模拟层（`lantern_sim`）

### 6.1 坐标与单位

- 世界单位和网页版的像素单位一致，所以数值表可以直接移植。y 轴向下，和旧版一致，由画面层负责翻转。
- 视野高度用固定的世界单位，宽度随窗口宽高比变化，最宽到 21:9。窗口越大，画面越清晰，但看到的范围不变，这样不同显示器上的游戏平衡是一样的。
- 模拟里的视野（刷怪圈、绕前距离）一律按最宽的 21:9 计算，与实际窗口无关，同一个种子在任何显示器上结果都一样，宽屏也看不到妖物凭空出现。

### 6.2 实体与数据

| 东西 | 存储方式 | 理由 |
| --- | --- | --- |
| 妖物 | 模拟内部的池子（`Enemies`，按字段分数组，槽位加代号的句柄） | 见下文 |
| 魂火（经验宝石） | 模拟内部的池子（`Gems`） | 数量大、行为单一，没人引用 |
| 主角、奇遇物件、地面区域（灵泉、地裂） | ECS 实体 | 数量少，各有行为，要挂不同的组件组合 |
| 伤害数字、粒子、墨迹 | 只在画面层有，模拟里不存在 | 纯视觉效果 |

**为什么妖物不用 ECS 实体**（M1 实现时改的决定）：
- 互推是按顺序原地修改位置的计算，结果取决于遍历顺序。如果妖物是 ECS 实体，画面层一给它挂上精灵组件，Bevy 就会把它挪到另一张表，遍历顺序随之改变，开窗口和不开窗口跑出来的结果就不一样，回放会失效。池子的遍历顺序只由模拟决定。
- 热路径（移动、互推、碰撞）连续访问同一字段，缓存友好，也没有创建和销毁实体的开销。
- 扩展性不受影响：妖物的种类、数值、移动方式都在数据里，状态效果（减速、冰冻、击晕、灼烧）是池子里的定长字段。

ECS 实体都有 `SimId(u32)`，按创建顺序递增，永不复用。对顺序敏感的逻辑用它打破平局，不依赖 Bevy 内部的 `Entity` 编号和查询顺序。

### 6.3 每一步的执行顺序

`FixedUpdate` 里用 `SimSet` 串成固定顺序：

```
Input（处理命令；选择阶段和演出停顿时只跑这一段）→ Player（移动、留火痕、回复、护盾、周期触发器、照见圈）
→ Director（刷怪、时间表、奇遇出现）→ Spatial（重建空间网格）→ Ai（夜主出招）
→ Move（妖物移动、互推、接触伤害）
→ Weapons（执行排队的触发器动作 → 法器 → 石印落地、地裂 → 轻功闪避伤敌 → 灯焰带
  → 反应区域（赤地、淤泥）→ 火痕 → 范围打击变成命中）
→ Projectiles（飞剑、金刃、弹幕）→ Collide（回光、九转金丹的震退）→ Damage（结算命中、命中触发器、印记与反应）→ Status（灼烧）
→ Death（掉落、击杀触发器、连斩、燃灯充能、击败夜主）→ Pickup（魂火、拾取物、灵草、奇遇触碰）
→ Progress（升级；倒下、天明、打开升级或宝箱）→ Cleanup → Hash
```

- 伤害只有一个入口：法器和飞剑产生 `Hit`，范围打击（寒波、石印、爆炸、震地、太极、燃灯）先排进 `Strikes`，在 Weapons 末尾按空间网格找目标再变成 `Hit`；Damage 阶段统一结算。反应产生的伤害追加到同一个队列的末尾，本步结算。
- 演出停顿（第一次发生某种反应时停 0.3 秒）记在模拟的 `Hold` 资源里：Play 阶段接下来几步只跑 Input，时间不走。停顿属于模拟，回放和不开窗口的重放结果一样。
- 触发器里不针对单个目标的动作（回复、爆炸、震地、全屏伤害、追加飞剑、天降宝箱）排进 `ActionQueue`，下一个 Weapons 阶段执行。连锁爆炸因此一步传一层，和网页版一致。
- `FixedUpdate` 用单线程执行器：系统本来就串行，省掉每个系统唤醒工作线程的开销（实测约占 15%）。
- 往同一个队列写数据的系统，一律在同一个 Set 里显式串行。系统内部可以用任务池并行，但只限“每个对象只读快照、只写自己”的计算（例如互推），这样怎么分线程结果都逐位相同。
- 从并行代码里不能创建实体或改动池子。需要创建的东西先放进队列，串行阶段再按顺序处理。

### 6.4 空间网格

以玩家为中心的均匀网格（格子 64），每一步用计数排序重建（移植网页版）。用于法器命中、选目标等查询：圆形范围、最近的 N 个、线段扫过的格子（后两种在 M2 加入）。

**互推**单独用一套结构（`crowd` 模块）。网页版的做法在 5000 只围成一团时，平均每只要比较约 200 个候选，真正重叠的只有个位数。现在的做法：
- 普通体型（半径不超过 19.5）放进边长 34 的细网格，刚好覆盖两只普通妖物的最小间距，只查相邻 3×3 格；精英和夜主数量少，单独列表，每只都直接比较。
- 推力按本步开始时的位置快照计算，算完一起写回（网页版是按顺序原地改），结果与遍历顺序无关，可以分线程并行。
- 重叠时的开平方放在不内联的函数里，避免编译器把分支改成无条件计算。
- 实测（云端 4 核 2.1 GHz，跑分模式 5000 只围着主角）：互推加其余模拟每步平均 0.95 ms；单线程 2.2 ms；优化前 5.7 ms。

### 6.5 伤害管线

```
命中来源（法器、飞剑、范围打击 Strikes → 按网格找目标；灯焰带、赤地、轻功）
  → HitQueue（按产生顺序）
  → Damage：冰冻（命中前）
    → 加成区（× 伤害属性；反应、赤地已经乘过，跳过）
    → 暴击区（战斗随机流；被击晕且有“土生金”必暴）
    → 易伤区（照见或光区、熔金、冰冻相加，上限 +150%）
    → 克制区（法器的五行克妖物 ×1.25、同系 ×0.8；妖物带五行时才有，抢先体验起）
    → 夜主单次封顶 → 扣血 → SimEvent::Hit
    → 命中、暴击触发器（灼烧、减速、冰冻立即生效；其余动作排进 ActionQueue）→ 击退（淤泥里 ×2）
    → 点燃（火·极境的爆炸）→ 五行印记与反应（`sim/reactions.rs`）
    → 活着的附加击晕、减速；死了的放进 Deaths
  → Status：灼烧扣血（每跳乘一次易伤），死了的也放进 Deaths
  → Death：掉落（掉落随机流）、击杀触发器、连斩、燃灯充能、击败夜主
```

- 灼烧和反应以触发那一击“加成区之后、暴击和易伤之前”的伤害为基数，暴击和易伤不会被算两次（docs/BALANCE.md 第 3.1 节）。
- 控制：冰冻、击晕、定身是硬控，晕头是软控；夜主免疫，精英时长减半，同一只精英 6 秒内第二次 × 0.5、第三次起 × 0.25（硬控、软控分开计）。减速同类取最大、上限 70%，夜主减半。
- **印记与反应**：法器命中带着五行，给妖物打上 3 秒的印记；带着印记的妖物被另一系命中就反应，印记清空。每只妖物每秒最多反应一次，每一步最多 64 次；反应、灼烧、共鸣效果、燃灯不带五行，所以反应不会引起反应。十种反应写在 `elements.ron`（效果是 `ReactionEffect` 的一个变体：蔓延灼烧、地面区域、金刃、冻结、灵草、蒸腾、熔金、斩击、地刺），区域同类对同一只妖物只算最强的一块，每类最多 64 块。**余印**：带印记的妖物死时（命中、灼烧都算，在 `combat::kill` 里），印记传给 `marks.spread_radius` 以内还没有印记的妖物，最多 `spread_count` 只，重新计时；按空间网格的查询顺序挑，结果是确定的。
- **照见圈**（`sim/reveal.rs`）：规则半径，和画面的灯光分开。基础 130，每升一级 +1%，最大 220；照见圈里的妖物易伤 +10%。灯芯 1 级起，圈边 20 宽的一圈是灯焰带，每 0.5 秒结算一次伤害。
- 每次命中按来源（法器、灼烧、连锁爆炸、太极、燃灯、各种反应、灯焰带……）累计实际打掉的血（`DamageLog`），平衡工具用它统计伤害占比。妖物池另记累计刷出的血量（`Enemies::spawned_hp`），主角受伤的事件带着是谁打的（`SimEvent::PlayerHurt { by: HurtBy }`：碰撞、冲锋、弹幕、九尾扫、狐火雨），平衡工具据此算刷出血量和死因。这两样都不进状态哈希。

### 6.6 构筑：属性、修正与触发器（扩展性的核心）

旧版和 lantern-next 把每级数值写成函数，五行共鸣写成 if 分支。桌面版统一成三个概念（`lantern_content::effects`，汇总在 `lantern_sim::stats`）：

**属性（Stat）**：伤害、范围、冷却、数量、暴击、击退、灼烧、冰冻易伤、飞行物速度与持续、减速与冰冻、反应伤害、召唤物倍率、生命、护甲、减伤、回复、护盾、治疗、移速、拾取、灯光、照见圈与照见易伤、灯焰带、燃灯充能、闪避（冷却、段数、距离、伤敌）、重抽、封印、选项数、灵光一闪、宝箱、刷怪、妖物血量与移速、精英数、奇遇频率、灯油与铜钱倍率、法器栏与灯坠栏、灯坠和心灯的规则参数（站定、火痕、照见圈外移速、冰冻魂火、受击反冻、回光、余烬），共 72 项，用一个枚举表示。基础值和上下限在 `stats.ron`。最终值 = clamp((基础值 + Σ加值) × (1 + Σ乘值), 下限, 上限)。伤害只许写 `Add`（加成区相加，内容校验会拒绝 `Mul(Damage, …)`）；暴击、易伤、克制是结算时的独立乘区。照见圈和灯光的“每级 +1%、+0.5%”在汇总时按等级加进乘值，升级时重算。

**修正来源**：心灯、局外属性、灯、灯坠（这四项是局外带进来的）、更、夜签、心法（每级）、五行共鸣各阶、相生、太极、古灯增益。规则开关 `Rule(…)`（无生、无月、夜主多一招、九转金丹）和“按共鸣阶数计”的 `ByTiers`（五帝钱）也在汇总时算出。来源变化时把属性标记为需要重算（`StatsDirty`），在下一个刷新点统一重算；周期触发器重算后保留已经过的时间。

**效果**写在数据里：

```ron
Add(CritChance, 0.10),                                            // 属性加值
Mul(Magnet, 0.25),                                                // 属性乘值
Trigger(on: Hit, action: Burn(duration: 3.0, ratio: 0.2)),        // 火·焚 一阶
Trigger(on: Crit, chance: 0.5, only: NotBonus, action: BonusSword(...)),  // 金·锐 三阶
Trigger(on: Kill, only: TargetFrozen, action: Explode(radius: 52.0, damage: (10.0, 5.0, 0.0), kind: Ice)),
Trigger(on: Periodic(30.0), action: ScreenDamage(damage: (40.0, 16.0, 0.0), boss_cap: 600.0)),  // 太极
Shield(amount: (20.0, 5.0, 0.0)),                                 // 土·固 一阶
Points(2), Favor,                                                 // 夜签“五行偏重”
```

- 时机：`Hit`、`Crit`、`Kill`、`ShieldBreak`、`Periodic(秒)`；条件：`TargetFrozen`、`NotBonus`、`ThirdHit`（同一只妖物的每第 3 次命中）；概率 `chance`。
- 动作：`Burn`、`Slow`、`Freeze`、`BonusSword`（每秒最多 30 把）、`Heal`（满血时多出的部分可以转成护盾）、`Explode`（可带冰冻、点燃）、`Quake`、`ScreenDamage`、`DropChest`。
- **共鸣**按投入计点（法器 Lv1–3 / 4–7 / 8 / 进化 = 1 / 2 / 3 / 4，心法 Lv1–2 / 3–4 / 5 = 1 / 2 / 3，表在 `elements.ron`），阈值 3 / 7 / 12 / 20 对应一阶到极境。标了 `superseded` 的一阶在到了下一阶后不再生效，由下一阶写的加强版取代（例如金·极境的“每次暴击都追加”取代三阶的“50% 追加”）。无属性心法（轻功、聚魂）不计点。
- **升级选项**：权重同网页版，已到一阶的五行 ×1.5；灵光一闪的概率是属性 `Inspiration`。保底：前 5 次升级至少出现 2 件不同的新法器；法器 Lv7 以上缺进化心法时，每次升级 25% 把那门心法放进选项（`run.ron` 的 `pity`）。封印（`SimCommand::Banish`）把选中的一项永久移出本局卡池，换一个新选项，次数来自属性 `Banishes`。
- 新增一种动作 = 给枚举加一个变体，再在 `lantern_sim::combat` 里写处理分支。之后任何法器、共鸣、夜签、心法都能用它。M2.5 的五行反应、灯坠按这个方式加（docs/GAMEPLAY.md 第 16 节）。

**法器** = 行为 + 每级数值表 + 五行 + 进化（进化后换一套同类行为的参数和数值）。行为在 `sim/weapons/` 里，一种一个文件：`Orbit` 环绕（灯火）、`Volley` 追踪齐射（符剑，也负责全部飞剑的飞行）、`Pulse` 震波（霜铃，进化后加全屏钟鸣）、`Seeker` 扑击（纸鹤）、`Drop` 落印（山印，进化后留地裂）。用已有行为做新法器，只需要写数据。

**妖物** = 数值 + 移动方式（追击、逃跑）+ 精灵 + 等级（普通、精英、夜主、奇遇小动物）。夜主的招式参数写在 `enemies.ron` 的 `boss` 里（弹幕、召唤），逻辑在 `sim/boss.rs`；M2.5 起每个夜主一个状态机。

### 6.7 模拟与外界的接口

| 方向 | 形式 |
| --- | --- |
| 输入 → 模拟 | 每一步一个 `InputFrame { mx: i8, my: i8 }`。摇杆和键盘的方向先量化成 i8 再交给模拟，实际游玩和回放看到的数值完全一样。 |
| 命令 → 模拟 | `SimCommand` 队列：闪避、燃灯、选择第几项、重抽、跳过、封印、确认（宝箱、进化演出）。每条命令带上步序号，写进回放。 |
| 模拟 → 外界 | `SimOutbox` 里一个 `Vec<SimEvent>`，存放小的 Copy 枚举（命中（带这一击的五行，画面按它上色）、击杀、拾取、受伤、闪避、升级、共鸣、进化、首领登场、震屏、闪光……）。一帧里可能跑了好几步，事件会累积起来；画面、音频、界面消费完之后，在 `Last` 阶段统一清空。Vec 保留容量，预热之后不再分配内存。 |
| 外界读取状态 | 直接查询组件和资源（只读）：`SimPhase`、`Flow`（当前的选项、宝箱、结算）、`Arsenal`、`Build`、`Stats`、飞剑、弹幕、拾取物、奇遇…… |

### 6.8 导演（单局节奏）

`assets/data/run.ron` 描述一局的全部节奏：总时长、刷怪速率曲线（再乘过渡系数，P0 是 0.7）、杂兵和精英各自的血量曲线、升级所需经验曲线、妖物配比、成群涌来的妖物、时间表、掉落、铜钱、点灯、升级选项权重、连斩、灯油。曲线用二次多项式系数表示。奇遇在 `events.ron`（间隔 40–65 秒）。夜签和“更”通过和属性一样的修正机制改这些参数（`SpawnRate`、`EnemyHp`、`EnemyDamage`、`BossHp`、`Affixes`……）。音乐强度由画面层按时间（3 分钟、6.5 分钟）和夜主是否在场决定。

- **上限**：常规刷怪按分钟分段停刷（300 / 600 / 1000 只）；妖群、合围、妖潮不受常规上限限制；任何刷怪都不超过硬上限 2000（`spawn_enemy` 里检查）。
- **时间表**（P0 青丘，docs/BALANCE.md 第 4.6 节）：精英、合围（预警 1 秒，画面上屏幕四边起墨雾；之后在视野外围成一圈，2.2 倍速合拢，进入 200 以内恢复原速）、5:00 小头目青面鬼（不带词缀，宝箱至少三连并优先升级最接近进化的法器）、精英、合围、8:00 妖潮、9:30 夜主（之后常规刷怪 ×0.4，并以主角为中心生成半径 600 的结界，主角出不去）。
- **更**（`difficulty.ron`）：每一更是一组修正效果，作为一个修正来源计入属性；三更的“夜主多一招”是规则开关 `Rule(BossExtra)`。`RunSetup.tier` 记在回放文件头里。
- **冲锋**（`enemies.ron` 的 `charge`，docs/BALANCE.md 第 12.6 节）：赤面狐扑击、青面鬼冲撞。妖物池里记阶段（冷却、蓄力、冲出、收势）、剩余时间和方向：离主角够近且冷却好了就原地蓄力（转向跟着主角，画面上身上发亮、地上画冲锋线；出手前 `lock` 秒锁定方向，线停下、变亮），然后冲出，接触伤害乘倍率，冲完原地停一会儿。冻住、击晕、定身、晕头会打断蓄力和冲锋。冲锋速度不吃“疾”“狂”和难度的移速加成。
- **精英词缀**（`affixes.ron`）：疾、坚、分、召、隐、狂；精英出场时按属性 `Affixes` 随机挑几个不重复的，记在妖物池的位掩码里。“隐”在照见圈外时自动瞄准锁定不到（空间网格的最近查询跳过它），范围伤害照样打得到。“分”死后分出几只小号（不算精英、不掉宝箱和铜钱）。
- **夜主**（`sim/boss.rs`）：九尾按生命分三个阶段：狐火环与召唤；分出幻身（`BossState.illusions`，不是妖物、打不死，在照见圈里待 0.5 秒就散）；九尾扫（扇形，预警后结算）。登场 120 秒后狂暴，攻击间隔 ×0.6；三更起全程多一招狐火雨。全部点亮石灯笼时夜主少两成生命。台词在 `enemies.ron` 的 `boss.lines`（登场、第二阶段、第三阶段、倒下；无尽夜里的退去、再来，docs/LORE.md 第 7 节）：换阶段、退去的那句出在提示条上，登场和天明的演出由 `moments.rs` 决定怎么用。
- **点灯**（`sim/lanterns.rs`）：开局把出生点周围分成 5 个扇区，每个扇区一盏，离出生点 600–1800。站在旁边累计 3 秒点亮，进入点灯奖励的选择阶段（回复、一次升级、铜钱）。点亮的灯是永久光区：区里的妖物减速、算被照见。
- **铜钱**（`sim/gold.rs`）：和魂火一样在模拟里，但不会自己飞回来；拾取范围、引魂铃会吸过来，天明时剩下的全部算进结算。倒下时已经捡到的全部保留。
- **燃灯**：每击杀一只妖物充“它的最大生命 ÷（基础刷怪曲线每秒刷出的总血量 × 40）”，精英额外 +15%；对夜主每次不超过最大生命的 2.5%。
- **货郎**：碰到后进入商店阶段，用铜钱买宝箱（`Choose(0)`）或一次灯坠三选一（`Choose(1)`）。
- **灯坠**（`sim/charms.rs`）：数值类的只是修正来源；规则类在模拟里结算——定海神针看主角站定的时间（`Player.still_t`），把站定、移动的加成算进加成区；风火轮在闪避路线上每隔一段留一段火痕，每 0.5 秒烧一次；照夜珠让照见圈外的妖物变快；冰魄珠让冰冻中死去的妖物魂火翻倍；霜瓷灯受击时按概率冻住攻击者。局内三选一：5:00 小头目必给，精英宝箱 30% 附带，货郎可买；只从 `RunSetup.charm_pool`（已解锁）里抽，不出已经挂着的、不出碎掉的金丹，法器多于 4 件时不出断剑。没有能给的灯坠时，宝箱改给 20 铜钱，货郎这一项灰掉（`Shop.charm_ok`）。
- **余烬**：开局第一步结束时打开一次只有心法的三选一（`Choice.ember`），权重同升级，能重抽、封印、跳过（跳过不给灯油）；选中的心法直接到节点等级。
- **减伤**：减伤合计（含定海神针的站定减伤）最多 60%。
- **救命**：致命一击落下时先试回光（心灯，留 1 点生命，2 级再回复 30%，震退周围），再试九转金丹（回复 50%，震退全屏、清掉弹幕，金丹碎掉）。记录在 `Survival`，同时记下受伤次数，用来判断“不受伤击败精英”。
- **灯笼叠层**（画面）：主角帧里只有灯杖，灯笼按这一局的灯画在主角上面：同一动作、同一朝向、同一帧号的 `lantern_<灯>/<动作>_<方向>_<帧号>`，自发光用它的 `_emit`；灯光半径不变，光色把灯的颜色淡淡地混进暖光。图集里没有这盏灯的叠层时不画灯笼，也不退回红纸灯。
- **结算统计**：`RunResult.feats` 记下见过的反应、太极、最高共鸣阶、手上同时最多几件法器、无伤击败的精英、受伤次数，存档按它判断成就。
- **10 分钟以后**（`run.ron` 的 `late`，docs/BALANCE.md 第 4.1 节）：刷怪、杂兵和精英生命改成线性增长，= 10 分钟时的值 × (1 + 斜率 × (m − 10))（`RunDef::late_at`）。普通一夜过了 10:00 的夜主战也按它算。
- **无尽夜**（`RunMode::Endless`，`run.ron` 的 `endless`，docs/GAMEPLAY.md 第 3.4 节、BALANCE.md 第 4.7 节）：前 10 分钟和普通一夜一样。夜主倒下不设 `won_at`，事件 `BossDefeated { dawn: false }`（画面和音效据此不演天明），结界撤掉，夜续下去。10 分钟以后每 5 分钟（15:00、20:00……）照时间表里的妖潮再来一次，妖潮结束时照时间表里的夜主再来；上一个还在场就等它倒下。第 k 次再来的夜主生命 × 1.25^k。进度记在 `Director.endless`（第几波、夜主该来的时刻、来过和倒下几次、10 分钟以后的击杀），无尽夜时进状态哈希。**夜深**（`endless.depth`，BALANCE 4.7）：10 分钟以后每过一分钟，杂兵和精英生命按 `hp_growth` 复利涨（取代线性的 `late.hp`，妖物池开局记下 `Enemies::endless`，`spawn::hp_curve` 按它挑曲线；燃灯的充能分母 `base_spawn_hp` 也跟着这条曲线），妖物移速（含冲锋）线性涨，魂火按 `xp` 复利打折，抗控制 r 线性涨到 `control_max`：冻住、击晕、定身的计时每步减 DT × (1 + 4r)，减速和击退 × (1 − r)；每次 10 分钟以后的妖潮发 `SimEvent::NightDeeper { layer }`，提示条写“夜深 · 第 N 层”。倒下才结束：灯油前 10 分钟照常，之后每秒 0.5、击杀 × 0.01，第一个夜主算天明 300、再来的每个 150；10 分钟以后铜钱掉落减半。`RunResult` 记 `endless` 和打倒的夜主数 `bosses`。

## 7. 确定性与回放

**规则**（`sim` crate 里用 clippy 的 `disallowed-methods` 强制执行）：

1. 步长是常量。不读系统时间，不读帧时间。
2. 所有随机数来自按用途划分的随机流：夜签、开局、刷怪、战斗、掉落、奇遇、选项、宝箱。每个流是一个 PCG32，由本局种子经过 SplitMix64 派生。
3. `sin`、`cos`、`atan2`、`exp`、`powf` 一律用 `bevy_math::ops`，并开启 `libm` 特性。直接调用 `f32::sin` 这类方法会报错。加减乘除和 `sqrt` 在各平台上都是 IEEE 精确的，可以直接用。
4. 不遍历 `HashMap` / `HashSet`。需要按顺序遍历的地方用 `Vec`、`BTreeMap` 或者排好序的数据。
5. 只在“每个实体只写自己”的地方使用并行，往队列里写的阶段一律串行。
6. 纯装饰的随机（粒子、震屏）放在画面层，用单独的随机数，不影响模拟。

**状态哈希**：每 60 步计算一次哈希。把实体按 `SimId` 排序，再把位置、血量、状态、随机流状态、玩家数据、构筑一起算出一个 u64。

**回放文件**（RON，格式版本 2）：
- 文件头：游戏版本、内容数据哈希、完整的开局设置 `RunSetup`（种子、模式、夜签、心灯等级）。
- 内容：按“步”录制。每一步的输入（游程编码），带步序号的命令，每秒（游戏时间）一个状态哈希。升级选择等阶段游戏时间不走，但这些步也录下来，选择命令记在它生效的那一步。
- 重放时逐秒核对哈希，不一致就报告第一次出现分歧的步数。
- 只有游戏版本和内容哈希都相同时才保证能重放。

**黄金测试**：固定几个种子，加上脚本化的输入，模拟 3 分钟，把每秒的哈希写进 `crates/sim/tests/golden/*.ron`。CI 在 Linux 和 Windows 上都跑这个测试并对照同一份文件，跨平台不一致会立刻发现。故意修改玩法时，用 `UPDATE_GOLDEN=1` 重新生成。

**录制与保存**（M1 已实现）：
- 每局都录，录制在模拟内部 `SimSet::Input` 的最前面完成，录到的就是模拟实际看到的输入和命令。
- 游戏中每 10 秒把当前回放写到数据目录的 `replays/current.ron`，万一崩溃，最近的一局也还在；一局结束时存成 `replays/<时间>-<种子>.ron`，只保留最近 20 局。
- 观看：`lantern --replay <文件>`，跳过标题直接开局，屏幕上方显示回放状态，与录制时的哈希不一致时提示从第几步起分歧，播完暂停。
- 校验：`lantern-tools replay <文件>`，不开窗口重放，逐秒核对。M1 实测：游戏里录的 30 秒回放，不开窗口重放 0.5 秒，30 个检查点全部一致（也就是说带画面、帧率不稳定的实际游玩，与不开窗口的模拟结果逐位相同）。M2 实测：游戏里录的 3 分 23 秒整局（含 11 次升级选择、夜签），203 个检查点全部一致。

**用途**：遇到 bug 时，把 `replays/` 里对应的文件发过来，我在云端用 `lantern-tools replay` 就能原样复现。

```
  run.ron          单局节奏与曲线、时间表、铜钱、点灯（第 6.8 节）
  meta.ron         心灯：用灯油点亮的功能节点（第 n 级花费 = 基础 × 1.6^(n−1)）
  attributes.ron   局外属性：用铜钱买（每级价格 = 基础 × 级 × (1 + 2% × 已买总级数)）
  lamps.ron        灯：起手法器、本命五行、灯性与代价、光色、一句话描述
  charms.ron       灯坠（带一句话描述）
  achievements.ron 成就：条件和奖励（开放基础、灯、灯坠、更、铜钱、灯油）
  hub.ron          灯驿人物的台词：按条件挑一句（docs/LORE-TEXT.md 第 1 节）
```

- 数据结构用 `serde` 定义在 `lantern_content` 里，游戏和命令行工具共用同一套。
- 加载后统一校验：ID 不能重复、引用必须存在、每种行为需要的数值都在、概率在 0 到 1 之间、效果只能用在允许的地方。`cargo test` 会校验仓库里的全部数据文件。游戏启动时如果校验失败，直接显示哪个文件出了什么错（RON 语法错误带行列号）。
- 文件里用字符串 ID（例如 `"sword"`），开局时转换成数组下标。
- 全部数据文件原文的哈希写进回放文件头，内容不同的版本重放时会提示。`hub.ron` 只有台词，不计入哈希。
- 灯坠、灯、奇遇的一句话描述（`flavor`，docs/LORE-TEXT.md 第 3 节）写在各自的数据里，没有就不显示。
- 名字和说明（法器名、心法说明、夜签好处……）目前直接写在数据里（中文）；界面上的固定文字写在 `crates/ui` 的代码里。`fonts.py` 扫描这两处裁剪字体。加第二种语言时再把文字移到 `assets/i18n/`，数据里改存文本键。

## 9. 画面（`lantern_view`）

### 9.1 图层（从下到上）

| 图层 | 内容 | 混合方式 |
| --- | --- | --- |
| 宣纸 | 平铺的纸纹 | 普通 |
| 地面 | 装饰、墨迹（环形缓冲，旧的逐渐淡掉） | 普通 |
| 影子 | | 正片叠底 |
| 角色 | 玩家、妖物、投射物，按脚底 y 排序 | 普通 |
| 暗层 | 光照图（9.2 节） | 正片叠底 |
| 火焰 | 灯笼火、法术特效 | 普通或叠加 |
| 自发光 | 妖物的眼睛、魂火、辉光 | 叠加 |
| 伤害数字 | 位图数字精灵（不用文本渲染） | 普通 |
| 屏幕效果 | 闪光、暗角 | 普通 |

- 角色用 Bevy 自带的 Sprite 加图集。z 值由图层基数加上 y 乘以一个小系数得到。同一张图集里的精灵会被自动合批，5000 只妖物大约只需要几次绘制调用。
- 妖物和魂火在模拟的池子里，画面层用一个固定大小的精灵池，每帧按池子的数据填充（只画视野内的），不随妖物生死创建、销毁实体。死亡特效由 `SimEvent::Kill` 另外生成。主角等 ECS 实体由 Observer 补上画面组件。

### 9.2 光照图

- 光源是带径向渐变的精灵，放在单独的渲染层上。一台光照相机把它们以叠加方式画到一张低分辨率的渲染目标上（屏幕的 1/2 到 1/4），底色是夜色 `#161B2C`。
- 再用一个全屏四边形，以正片叠底的方式把这张图盖到角色层之上。
- 自发光层在暗层之上，所以暗处也能看到妖物的眼睛。
- 叠加和正片叠底的实现（M1 已验证）：Bevy 0.20 的精灵只有普通混合，这里用 `ExtendedMaterial2d<ColorMaterial, 混合扩展>`，着色器沿用 Bevy 自带的，扩展只在 `specialize` 里改渲染管线的混合状态，不用自己写着色器。图集的每一帧做成一个带对应纹理坐标的四边形网格并缓存，同一页贴图、同一种颜色的共用一个材质，可以合批。
- 光照图是窗口分辨率的一半；窗口改变大小时跟着改。光照相机和主镜头同步，暗层是一个铺满镜头的四边形。
- 光源：灯笼（灯笼挂点，逐帧逐方向）、灯火、魂火（最多 200 个）、石灯笼（灯火挂点）、击杀闪光（0.3 秒，精英加倍）。颜色、半径照 docs/PORTING-NOTES.md 第 7 节。
- 辉光：主镜头开 HDR 和 Bevy 自带的 Bloom（叠加模式，阈值 1.0）；画在主画面上的自发光亮度乘 `EMIT_HDR`（1.5），叠起来超过 1 的部分才晕开，纸面和墨色不受影响。设置里可关。
- 光照图的底色平时是夜色，夜主登场时压暗，天明时 3 秒内变成晨光（`atmos.rs`，docs/FEEL.md 第 4 节）。暗层的大小按窗口比例当场计算，跟着主镜头缩放、侧倾。

### 9.3 动画、镜头与特效

- **动画**：帧名形如 `hero/walk_SE_05`（第 15 节），开局前按名字查好“动作 × 方向 × 帧”的表，每帧不再查字符串。主角朝向带滞后（偏离扇区中心超过 22.5° + 0.12 弧度才切换）；走路动画按移动距离推进（`stride_units`），待机、闪避按时间推进；倒下时播放一次 death。妖物按 fps 播放、每只错开相位，朝向玩家时左右镜像，受击 0.08 秒内换白色剪影帧，浮空的上下浮动。
- **镜头**（`camera.rs`）：跟随插值后的玩家位置，移动方向上略微前瞻；创伤式震屏（平滑噪声，带一点侧倾）、方向冲击、只往里推的缩放冲击。顿帧和慢镜只调 `Time<Virtual>` 的速度，模拟照样逐步推进，不影响回放。各事件的参数见 docs/FEEL.md 第 2 节。
- **粒子**（`particles.rs`）：固定容量的 CPU 粒子池，不创建实体，每帧攒成绘制请求写进精灵池和发光池；贴图在启动时用代码画好，作为图集的一页（`AtlasDb::add_page`）。需要上万粒子时再考虑 GPU 粒子。
- **地面装饰**：用本局种子派生出画面专用的随机数，同一个种子每次看到的地面一样，但不消耗模拟的随机流。P0 只有青丘，通用的草和墨晕之外铺青丘的 `qq_` 装饰，偶尔摆石狐、狐仙祠、狐灯；发光道具的光色、光半径取素材 meta 的 `light_color`、`light_radius_units`，光放在 `glow` 挂点。以后有了地区，再按地区挑装饰。
- **法器与法术（M2）**：`fx.rs` 参照网页版 `render/weaponViews.ts`。持续存在的东西（飞剑、纸鹤、石印与预警、地裂、护盾、拾取物、夜主弹幕、奇遇道具）每帧直接读模拟资源，画进同一个精灵池；一次性的效果（各种环、印痕、连锁爆炸、太极、燃灯）收到 `SimEvent::Strike { fx, .. }` 等事件后记在 `FxState` 里自己计时淡出。地面上的圆按透视压扁（×0.62）。
- **震屏与闪屏**：都在画面层，由事件触发（落印、地裂、燃灯、夜主登场、受伤），不影响模拟。
- **伤害数字**：96 个 `Text2d` 的环形池，按 28 号字栅格化后缩小到世界单位；普通数字按五行上色，暴击用毛笔字、金色、盖章式弹出。反应名在发生的地方飘出毛笔小字（12 个的环形池）。墨点（最多 160 个）和击杀闪光也在 `effects.rs`。
- **氛围**（`atmos.rs`）：萤火、夜雾、暗角（Bevy 的 `Vignette`，受伤和濒死时变化）、受伤时的色差、天明。

### 9.4 画质设置

设置菜单里提供：渲染分辨率比例、光照图精度、辉光开关、粒子密度、垂直同步、帧率上限，以及低、中、高三档预设。网页版的自动降画质是为手机设计的，桌面版默认不用；调试面板里保留开关。

目前做了：辉光开关；特效“完整 / 精简”（精简时粒子减半，不画萤火、夜雾和色散，见 `docs/FEEL.md` 第 7 节），设置里是 `lite_fx`，同步到画面层的 `Feel::lite`。

## 10. 音频（`lantern_audio`）

- kira 0.12，两条子轨：音效（+7 dB，和网页版响度对齐，挂压缩器）和音乐。音乐轨挂一个低通滤波器，暂停、升级、开宝箱时把截止频率压低，听起来变闷。两条轨都送一点到混响发送轨。音量来自设置，改了立即生效。
- **乐器**（`synth.rs`）：把 `web/lantern/audio.js` 的合成算法（古筝式拨弦、编钟、太鼓、木鱼、锣、滤波噪声）移植成 Rust。启动时一次性合成为采样缓冲区（拨弦按五声音阶每个音一份，三种衰减），运行时只负责播放，CPU 开销接近零。还有一段可循环的低音持续音（drone）。
- **音乐**（`music.rs`）：按本局种子生成动机，每小节变奏。每帧往前看 0.2 秒，把这段时间里要响的音用 kira 的 `StartTime::Delayed` 预先排好，节拍不受帧率抖动影响。模式：标题、单局、夜主；单局里的强度按时间分三档（3 分钟、6.5 分钟），逐档加木鱼、太鼓。
- **音效**（`sfx.rs`）：把 `SimEvent` 映射到声音。同类声音有最小间隔，连续拾取魂火时音高逐步升高，连斩、升级、进化、开宝箱（按稀有度三档）、夜主登场各有专门的声音。有位置的音效按相对主角的左右做声像、按远近衰减；濒死时有心跳，夜主倒下时全场静半拍（docs/FEEL.md 第 6 节）。
- 音频只消费事件，不影响模拟。没有声卡时自动静音，继续运行。

## 11. 界面（`lantern_ui`）

- 用 `bevy_ui` 做：标题（出发、灯驿、设置、跑分、退出）、出发准备（通关一更后可选玩法：夜行或无尽夜，无尽夜只能选通关过的更；选更、择灯、挂灯坠、选悟、开关属性）、夜签选择、灯驿（老灯匠·心灯、货郎·属性、灯童·成就、说书人·图鉴，`hub.rs`；每个人物的卡片上说一句台词，由 `Profile::hub_line` 按 `hub.ron` 的条件挑：第一次见面说 First，其余取满足的最后一条，都不满足时轮着说“平时”。“刚发生的事”记在不存档的 `HubNews` 里：结算时比较记进存档前后的变化，在灯驿里点亮心灯、退还属性时也记）、游戏中的信息栏（生命、经验、护盾、时间、击杀、连斩、燃灯、法器与心法栏、五行点数、夜主血条、增益）、升级三选一（重抽、跳过）、宝箱、进化展示、点灯奖励、货郎、灯坠三选一与替换、余烬的开局心法三选一、暂停（继续、音量、全屏、回到标题）、结算（新纪录、新成就）、提示条。第一夜之前灯驿锁着，出发直接开局（一更、红纸灯、不抽夜签）。
- **皮肤**：美术管线输出的九宫格贴图在 `assets/atlas/skin/`，`skin.json` 记录每张图的切边（左、上、右、下，按 2 倍绘制）。`skin.rs` 读它，`Skin::image(名字)` 返回切好边的 `ImageNode`。贴图画在边框盒上（`VisualBox::BorderBox`），不受内边距影响。卡片按稀有度换底，选中时叠一层高亮框。
- **导航**：没用 `bevy_input_focus`，每个界面自己记一个选中下标，读平台层的 `Actions`（方向键或十字键切换，回车或 A 键确定，数字键直选，R 重抽，X 跳过，Esc 返回）。鼠标悬停改选中项，点击等于确定。所有界面都可以不用鼠标操作。
- **只读模拟**：升级卡片、宝箱、结算都只读 `Flow`、`Build`、`Arsenal` 等资源，玩家的选择发 `SimCommand::Choose / Reroll / Skip / Ack`。卡片上的说明文字（升级前后的数值、新心法、进化）由 `describe.rs` 根据内容数据生成。
- 字体：标题用 Ma Shan Zheng，正文和数字用 Noto Serif SC（都是 OFL 协议）。`crates/ui/fonts.py` 收集界面代码和 `assets/data/` 里所有非 ASCII 字符，裁剪出子集（目前两款合计约 300 KB，完整字体约 31 MB）。新增文字后要重新运行这个脚本；CI 用 `--check` 检查缺字。Ma Shan Zheng 没有“·”，标题字体的文字里自动换成“•”。
- 文字：界面固定文字仍写在 `crates/ui` 的代码里，名字和说明在 `assets/data/`。加第二种语言时再统一移到 `assets/i18n/`（第 8 节）。
- 性能面板（F3）：帧率、帧时间、模拟每步耗时（FixedUpdate 首尾计时，只做诊断）、画面层每帧耗时（`ViewStats`）、妖物和魂火数量、精灵、发光与粒子数量。egui 调试面板（实时开关光照、调整妖物数量、无敌、加速）在需要时再加，只在 `dev` 特性下编译。
- 跑分（标题界面按 B）：依次保持 250、1000、2500、5000 只妖物，各 10 秒（前 3 秒不计），主角无敌、自动绕圈；结束后显示结果，并存到数据目录的 `bench/bench-<时间>.txt`，内容包括显卡、窗口大小、每段的帧率、95% 帧时间、最长帧和模拟耗时。

## 12. 平台（`lantern_platform`）

**输入**：键盘（WASD 或方向键移动，空格或 Shift 闪避，E 或 F 燃灯，Esc 暂停）、手柄（左摇杆移动，A 或 RT 闪避，Y 或 RT2 燃灯，Start 暂停），鼠标只用于点菜单。自己写一层“按键 → 动作”映射（`Actions`），之后可以在设置里改键。单局进行中（`SimPhase::Play`）才把移动、闪避、燃灯送进模拟，量化成 `InputFrame`；选择阶段的按键由界面翻译成 `SimCommand`。

**数据目录**（通过 `directories` 获取）：
- Linux：`~/.local/share/lantern/`
- Windows：`%APPDATA%\lantern\data\`

| 文件 | 内容 |
| --- | --- |
| `save.ron` | 局外进度（`Profile`，第 2 版）：灯油和铜钱（余额、累计）、心灯等级、局外属性等级与开关、解锁的灯和灯坠、开放到第几更、成就、见过的反应、上次的选择（含是否走无尽夜）、见过的灯驿人物、最佳记录、无尽夜各更的最长存活（`endless`）、累计统计、局数和胜场 |
| `settings.ron` | 全屏、垂直同步、音乐和音效音量（画质、语言、按键以后加） |
| `replays/` | 最近 20 局的回放 |
| `logs/` | 运行日志（保留最近 5 份） |
| `crash/` | 崩溃报告：panic 信息、调用栈、当局回放 |

- 存档和设置都带 `version` 字段，每次升级格式时写一个迁移函数，旧存档逐级迁移。读不了的文件改名备份后用默认值，不让游戏起不来。
- 一局结束时结算界面调用 `Profile::record`：加灯油和铜钱、更新统计和最佳记录（无尽夜只记在它自己的榜上，按更分开）、判断成就并立即发奖（成就发的灯油和铜钱不乘倍率）；看回放、跑分、无敌模式不计。心灯、属性在标题界面（M2.5-4 起是灯驿）花钱升级，开局时写进 `RunSetup`，所以回放能重现。属性可以全部退还（返还实际花掉的铜钱），也可以出发前单独关掉。
- **M2 存档迁移**（docs/BALANCE.md 第 10.6 节）：读到第 1 版存档时，内容加载好后由 `Profile::upgrade` 迁移一次——锋芒、体魄、灵巧清零并退回灯油，祈福保留等级，铜钱从 0 开始，按局数和胜场补发前 3 个成就。
- 写入时先写临时文件，再改名替换，并保留上一份备份。断电或崩溃不会把存档写坏。
- 以后接 Steam 时，用 `steam` 特性开关 `steamworks`，负责成就和云存档，默认不编译。

## 14. 构建与发布

**编译配置**：
- `dev`：自己的代码用 `opt-level = 1`，依赖用 `opt-level = 3`（Bevy 官方建议）。Linux 上可以开 `bevy/dynamic_linking` 加快增量编译。
- `release`：`lto = "thin"`、`codegen-units = 1`、`strip = true`。
- Windows 发布版不弹出控制台窗口。

**资源目录**：开发时用仓库根目录的 `assets/`，发布时用可执行文件旁边的 `assets/`。

**CI（`ci.yml`）**：桌面版相关的路径有改动时运行。
- Linux：`fmt`、`clippy -D warnings`、`test`。
- Windows：`test`，主要为了跨平台确定性的黄金测试。

**发布（`release.yml`）**：推送 `v*` 标签时运行。
- Linux：在较旧的 Ubuntu 上构建，兼容更多发行版的 glibc，产物为 `lantern-<版本>-linux-x86_64.tar.gz`。
- Windows：用 MSVC 构建，产物为 `lantern-<版本>-windows-x86_64.zip`。
- 两个包都上传到 GitHub Releases。
- 以后再加 AppImage、Windows 安装程序、Steam 上传。

**网页站点**：`pages.yml` 只在 `web/` 有改动时运行，桌面版的提交不会触发网页部署。仓库的 Pages 来源是“GitHub Actions”。

## 15. 美术管线对接

管线本身的说明见 `docs/PORTING-NOTES.md` 第 8 节和 `art/README.md`，这里只记 Rust 端依赖的约定。Rust 端只读 `assets/atlas/`，不读 `art/out/`。

- `art/` 从 `lantern-next/art/` 移到了仓库根目录，命令在仓库根目录执行。
- **出图密度**：桌面版用 `LANTERN_ART_DENSITY=2`，即 **4 像素 / 世界单位**（网页版是 2）。视野高 420 个世界单位，1440p 下每个世界单位约 3.4 像素，略微缩小显示。中间产物在 `art/out/assets@2x/`，打包后放到 `assets/atlas/`。`web/lantern-next/public/assets/` 保持 1 倍密度，不再更新。
- **图集文件**：`assets/atlas/` 下有：

- **图集格式**：TexturePacker hash 格式 JSON + PNG（直通 alpha，未预乘，颜色已扩散到透明像素）。每帧有：
  - `frame`：在图集页里的矩形；
  - `sourceSize`：原图尺寸；`spriteSourceSize`：裁掉透明边后剩下的部分在原图里的位置和大小；
  - `anchor`：相对原图尺寸的锚点。角色和小妖 `(0.5, 0.875)`，石妖、精英、夜主、场景道具 `(0.5, 0.8)`；特效多为 `(0.5, 0.5)`。
- **`meta.lantern`**（每页都有）：
  - `pxPerUnit`：这张图集的密度。精灵的世界尺寸 = 像素尺寸 ÷ `pxPerUnit`，Rust 端不要写死。
  - `page`、`pages`：页号和总页数。多页时文件名是 `<图集>_<页号>.json/png`，`meta.related_multi_packs` 列出其他页；单页时就是 `<图集>.json/png`。
  - `frames`：本页每帧的 `{"blend": "normal" | "add", "tint": bool}`。`tint: true` 的帧是白色或灰度的，用时乘颜色；`blend: add` 的帧画在叠加层。特效、地面、界面帧还可能带素材 meta 里的其他标量字段，例如 `radius_px`（反应区域、扇形的半径）、`angle_deg`、`flat`、`stretch`、`width_px`，界面帧带 `kind`、`id`、`name`。像素单位都是本图集的像素，换算到世界单位除以 `pxPerUnit`。这些字段都是可选的，读取时不认识的字段忽略即可。
  - `assets`（只在第 0 页）：每个角色素材的 `meta.json` 原样保留（妖物只有 E 方向，道具只有 `idle` 的 S 方向 1 帧），包括 `size`、`anchor`、`px_per_unit`、`anims`（每个动画的 `frames`、`fps`、`dirs`、`loop`、`stride_units`、`windup_frames`、`loop_from`，见下面“妖物动作”）、逐帧挂点 `sockets`（单位是图集像素，相对锚点即脚底，x 向右、y 向下；换算到世界单位同样除以 `pxPerUnit`），以及 `shadow_radius_px`、`floating`、`category`（hero / enemy / elite / prop）、`anchor_kind`、`vertical_motion` 等。挂点：主角 `lantern`，妖物 `eyes`（竹魅另有 `muzzle`），石灯笼、古灯和货郎担 `flame`，血祭坛、狐仙祠 `glow`，狐灯 `glow` 和 `glow_0..2`。`game_radius` 只用来对齐画面，碰撞半径以 `assets/data/` 的妖物数据为准。`floating: true` 表示悬浮的妖物（影妖、疾影、狐火），游戏里给它们加上下起伏；`register_x_only` 只给美术自检用，可以忽略。
- **动画序列**：`animations`（只在第 0 页）把 `<素材>/<动画>_<方向>` 映射到有序的帧名列表；`_flash`、`_emit` 各有自己的序列，例如 `hero/walk_E_emit`。多页时帧可能落在任何一页，加载时先合并所有页的 `frames`。
- **帧名与方向**：
  - 帧名形如 `<素材>/<动画>_<方向>_<两位帧号>`，例如 `hero/walk_SE_05`；
  - 白色剪影帧（受击闪白）加 `_flash`，自发光层加 `_emit`，例如 `shade/float_E_03_emit`；
  - 方向依次为 `E SE S SW W NW N NE`，y 轴向下；
  - 妖物只画 E 方向，往西走时左右镜像；主角 8 个方向都有，不镜像（灯笼始终在右手）。
- **白色剪影帧**：`_flash` 是纯白剪影，尺寸、锚点和普通帧相同。受击时整帧换成它（普通混合），不是叠加。主角没有剪影帧。
- **自发光层**：`_emit` 帧和对应的普通帧尺寸、锚点完全相同，叠加画在暗层之上，所以暗处也能看到灯笼窗、妖眼。没有自发光部件的素材没有 `_emit` 帧。
- **主角动画**：`idle`（6 帧）、`walk`（8 帧，按移动距离推进，`stride_units` 是一个循环走过的世界距离）、`dash`（4 帧 @16 fps）、`hurt`（2 帧 @10 fps）、`death`（6 帧 @8 fps，不循环），各 8 个方向。主角帧里只有灯杖，没有灯笼头，也没有 `_emit`。
- **灯笼叠层**（一位主角，换灯只换叠层）：
  - 每盏灯一套和主角帧**同画布、同锚点**的逐帧叠层：`lantern_<灯>/<动画>_<方向>_<帧号>`，以及 `_emit`（灯芯，叠加）。动画、方向、帧数和 `hero` 完全一致。
  - 渲染时主角身体和灯杖当遮挡，被挡住的部分已经是透明的。所以游戏在主角帧之上原样叠画即可（同位置、同锚点，z 略高于主角），不用处理前后关系。
  - 灯的 id 和 `assets/data/lamps.ron` 一致：目前有 `red`（红纸灯）、`mirror`（铜镜灯）、`frost`（霜瓷灯）。以后的灯照同样规则加帧，id 以 lamps.ron 为准。没有灯笼的灯（无灯）什么都不画，不要回退到红纸灯。
  - 叠层的 `meta.lantern.assets.lantern_<灯>` 有 `category: "overlay"`、`base: "hero"`、`lamp`、`lamp_name`、`light_color`（与 lamps.ron 的 color 一致，以内容数据为准）。主角的 `assets.hero.overlays` 列出现有的叠层。
  - 灯光位置照旧用主角的 `lantern` 挂点。铜镜灯的铜镜在灯芯后面当反光镜，背面朝向（N、NE、NW）时灯芯被挡住，`_emit` 帧接近全透明，属正常现象，光源照常放。
  - 倒地动画里灯笼落在地上，灯芯渐暗，三盏灯一致。
- **宣纸**：不透明 RGB PNG，1024×1024，无缝平铺，1 纹素 = 0.25 世界单位（一张覆盖 256 个世界单位）。
- **染色建议**（`tint: true` 的帧本身是白的）：妖眼按妖物种类染色；`weapons/foxfire_*` 染 `#FF6B5A`；`weapons/bamboo_spike_trail` 染 `#A8E6B8`；`vfx/mist_*` 染 `#DDD9CF`；`ground/rift_glow` 染 `#D2386A`；`weapons/sector`、`sector_fill` 染 `#FF4A3A`（叠加；照亮的宣纸上会发白，亮处可改用普通混合）；`ground/zone_lava_glow` 染 `#FF7A2A`，`ground/zone_herb_glow` 染 `#9CF0B8`。`vfx/flame_*`（灯火火焰）带颜色、普通混合，火焰尖端的墨色要保留。
- **锚点补充**：芦苇、竹子、竹笋 `qq_shoots_*` 的锚点在底边 `(0.5, 1.0)`；其他地面装饰居中。`qq_wash_*` 的 meta 有 `max_alpha: 0.3`（整张最浓处的不透明度），`qq_fox_tracks` 已压扁成地面透视（`flat: 0.7`）。
- **扇形预警**：`weapons/sector` 是 120° 扇形，锚点在扇形顶点（`(0.0625, 0.5)`），开口朝 +X，2 倍下半径 128 像素，按需要的半径缩放、按方向旋转；`sector_fill` 是同形的填充层，蓄力时从顶点向外放大。
- **平时的动作**：有好几个动作的素材在 `meta.lantern.assets.<素材>.default_anim` 写平时循环的动作名；没写时用 `move`，再没有取名字排在最前的（`AssetMeta::default_anim`）。
- **妖物动作**（青丘包起）：
  - `windup_frames: n`：出手动作的第 0 到 n−1 帧是蓄力。预警一开始播这几帧，然后停在第 n−1 帧（最后一个蓄力帧）等预警结束，再从第 n 帧接着播。目前都是 2：赤面狐 `pounce`、青面鬼 `charge`、狐火 `pounce`、竹魅 `shoot`、九尾 `sweep`。
  - `loop: false`：播一遍停在最后一帧，播完回到平时的动作。上面这些出手动作、九尾 `summon`、讨封狐 `reveal` 都是。没写 `loop` 的动作循环。
  - `loop_from: n`：播完后从第 n 帧起循环，直到这一招结束。目前只有青面鬼 `charge`（第 0–1 帧蓄力，2–5 帧是冲锋的跑步循环）。
  - 游戏里怎么用（`crates/view` 的 `actors.rs`）：有冲锋的妖物播素材的 `pounce` 或 `charge`，模拟蓄力时播蓄力帧，冲出去接着播，停下以后没播完的播完再回到平时；九尾扫预警时蓄力、落下时扫过去，召唤和狐火雨时播 `summon`。出招时朝着招式的方向，不再朝着主角。没画出手动作的妖物照旧播平时的动作。
  - 新妖物的 `eye_color`（妖眼染色，写进 enemies.ron）：狐火 `#F2FFFC`、竹魅 `#9BF5C9`、讨封狐 `#FFD23F`。
  - **狐火** `fox_wisp`：`float` 8 帧（平时，悬浮）、`pounce` 4 帧（绕圈后扑出）。身体是青白的火，夜里整只发光，不只是眼睛。
  - **竹魅** `bamboo_wraith`：`idle` 4 帧是藏在竹丛里（面具半露，眼睛暗淡），`move` 6 帧，`shoot` 5 帧（竹枝甩出竹刺）。竹刺从 `muzzle` 挂点出手，挂点每帧都有，只在 `shoot` 有意义。
  - **讨封狐** `taofeng_fox`：`disguise` 6 帧是斗笠蓑衣的路人（平时的动作，`_emit` 是空的，眼睛不亮），`reveal` 4 帧甩掉蓑衣现形（眼睛亮起），之后用 `move` 6 帧。进照见圈时播 `reveal`。

- **界面皮肤 `skin/`**：给 `ImageNode` + `TextureSlicer` 用的九宫格图，直通 alpha，不裁边。
  - 清单格式：`{"scale": 2, "items": {"<名字>": {"file", "size": [w, h], "slice": [左, 上, 右, 下], "center": "stretch"|"tile", "sides": "stretch"|"tile", "text": "#rrggbb", "note": "用途"}}}`。`slice` 全 0 的是固定尺寸的图（槽位、圆点、箭头），不切；`text` 是建议的文字颜色；`arrow_marker` 另有 `"tint": true`（白色，按奇遇颜色染）。

## 18. 风险

| 风险 | 应对 |
| --- | --- |
| Bevy 每隔几个月就有不兼容的更新 | 锁定 `=0.20.0`；只在里程碑之间升级；少用第三方 Bevy 插件；模拟层只依赖 ECS，这部分 API 相对稳定 |
| Rust 编译慢 | 调整 dev 配置，开动态链接；CI 缓存 `target/` |
| 云端没有显卡，看不到真实画面 | 用 lavapipe 截图做冒烟测试；观感和帧率以你本机为准；调试面板和跑分结果卡可以一键复制，方便反馈 |
| 跨平台浮点结果不一致，回放失效 | 用 `libm` 计算超越函数，clippy 禁用 `std` 的浮点数学方法，黄金测试在两个平台上对照 |
| Linux 发行版差异 | 在较旧的 Ubuntu 上构建；同时支持 Wayland 和 X11；发布说明里列出依赖（ALSA、udev、Vulkan 驱动） |
| 两个会话同时修改仓库 | 按目录分工（第 19 节），推送前先 `git pull --rebase` |
